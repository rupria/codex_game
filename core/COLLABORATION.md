# 협업 및 동시 작업 규칙

이 저장소와 상위 Google Drive의 공유 문서는 여러 작업자가 동시에 사용할 수 있습니다. 모든 변경은 다른 작업자의 진행 중인 작업을 보존하는 것을 우선합니다.

## 작업 시작 전

- 대상 파일을 작업 직전에 다시 읽습니다.
- `git status --short --branch`로 추적·미추적 변경을 확인합니다.
- 최근 수정 시각과 새로 추가된 파일을 확인합니다.
- 기존 변경은 작성자가 명확하지 않아도 사용자 또는 다른 작업자의 작업으로 간주합니다.
- 같은 파일이나 같은 기능 영역에서 동시 변경이 의심되면 덮어쓰지 않고 변경 범위를 분리합니다.

## 변경 원칙

- 필요한 줄과 파일만 수정하는 작은 패치를 사용합니다.
- 관련 없는 변경을 정리하거나 되돌리지 않습니다.
- 다른 작업자의 미완성 코드나 문서를 임의로 완성·삭제·이동하지 않습니다.
- 대규모 파일 교체, 강제 푸시, 강제 초기화와 이력 재작성은 하지 않습니다.
- 충돌 가능성이 큰 작업은 별도 파일, 별도 모듈 또는 별도 브랜치로 분리합니다.
- 문서에 확인되지 않은 일정, 담당자, 기술 선택이나 완료 상태를 확정값처럼 기록하지 않습니다.

## 공유 문서 원칙

- 문서별 기준 원본이 정해지기 전에는 Google Drive 문서와 저장소 문서를 동시에 독립 수정하지 않습니다.
- 동일 내용을 여러 위치에 복제해야 하면 기준 원본과 동기화 책임을 문서에 표시합니다.
- Google Drive 동기화 중인 파일은 충돌 사본이나 잠금 상태를 확인한 뒤 수정합니다.
- 삭제가 필요한 문서는 즉시 삭제하지 않고 보관 위치와 이유를 먼저 합의합니다.
- 의사결정, 에셋 권리와 검증 결과에는 날짜와 근거를 남깁니다.

## Git 작업 원칙

- 한 커밋에는 하나의 명확한 목적을 둡니다.
- 커밋 전 변경 파일과 diff를 다시 확인합니다.
- 다른 작업자의 변경이 섞여 있으면 소유 범위를 확인하기 전 함께 커밋하지 않습니다.
- 원격 변경을 가져오기 전 로컬 미커밋 변경과 충돌 가능성을 확인합니다.
- 푸시 또는 PR 생성은 변경 범위와 대상 브랜치를 확인한 뒤 진행합니다.

## 충돌 또는 불확실성 대응

다음 상황에서는 추측하여 덮어쓰지 않고 작업을 멈춘 뒤 조정합니다.

- 작업 중 대상 파일의 내용이나 수정 시각이 예상과 다르게 바뀐 경우
- 동일 기능을 구현하는 새 파일이나 브랜치가 발견된 경우
- 어떤 문서가 기준 원본인지 판단할 수 없는 경우
- 다른 작업자의 변경과 현재 작업을 분리할 수 없는 경우
- 삭제, 이름 변경 또는 구조 이동이 다른 작업에 영향을 줄 수 있는 경우

## 작업 완료 시

- 변경 파일, 검증 결과와 남은 위험을 기록합니다.
- 새 문서나 기능이 기존 인덱스·README에서 탐색 가능한지 확인합니다.
- 커밋·푸시 여부와 Google Drive 동기화 여부를 구분해서 알립니다.
- 후속 작업자가 바로 이어갈 수 있도록 미결정 항목과 다음 행동을 남깁니다.
