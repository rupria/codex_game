# PM·QA 협업 운영 규칙

- 문서 책임: PM·QA
- 적용일: 2026-08-05
- 적용 범위: 일정, 의존성, 위험, 검증, 릴리스 게이트와 제출 준비

## 역할 경계

PM·QA 담당자는 다음 작업만 수행한다.

- 프로젝트 일정, 마일스톤, 우선순위와 의존성 관리
- 작업 상태, 차단 요소, 위험과 특이사항 추적
- 완료 조건과 테스트 기준 작성
- 빌드 검증, 결함 재현, 심각도 판정과 결과 기록
- D-5 플레이 가능 빌드와 D-3 실제 제출 게이트 운영
- 기획·개발·아트·배포 담당자에게 필요한 입력과 수정 요청 전달

다음 작업은 담당 영역의 명시적인 요청 없이는 수행하지 않는다.

- 게임 콘셉트, 규칙, 세계관과 콘텐츠의 최종 결정
- 게임 코드, 빌드 설정과 기술 구조의 구현 또는 수정
- 이미지, 음원, 영상과 발표 자료의 제작
- 담당자의 결정을 대신하는 범위 변경

PM·QA는 위 산출물을 직접 수정하는 대신 완료 조건, 검증 결과, 일정 영향과 필요한 후속 작업을 기록한다.

## 동시 작업 규칙

1. 작업 시작 직전에 Git 상태와 대상 파일의 최신 내용을 확인한다.
2. 다른 작업자가 만든 변경은 삭제, 이동, 재작성하지 않는다.
3. 공용 로그는 기존 항목을 덮어쓰지 않고 새 항목을 추가한다.
4. 상태를 변경할 때 작성자, 변경 시각, 근거 링크 또는 빌드 식별자를 남긴다.
5. 문서 간 내용이 충돌하면 임의로 하나를 채택하지 않고 `RISKS.md`에 차단 요소로 기록한다.
6. 기획 또는 코드 변경이 필요하면 해당 담당자에게 이슈로 요청하고 PM·QA는 직접 수정하지 않는다.
7. 검증 결과가 없는 작업은 `Done`이 아니라 `Validation` 상태로 둔다.

## 상태 정의

| 상태 | 의미 |
|---|---|
| Backlog | 우선순위와 일정이 확정되지 않음 |
| Ready | 담당자, 완료 조건과 선행 작업이 확정됨 |
| In Progress | 담당자가 현재 작업 중 |
| In Review | 담당 영역의 검토 진행 중 |
| Validation | 실행 가능한 산출물을 QA가 검증 중 |
| Blocked | 외부 결정, 권한 또는 선행 작업 때문에 진행 불가 |
| Done | 완료 조건과 필요한 검증을 모두 통과함 |
