# Team Workflow

## 목적

기획, 프로그래머, QA와 PM의 업무가 문서 작업공간과 GitHub 사이에서 누락되지 않도록 책임과 인계 조건을 정의합니다.

## 기준 위치

| 내용 | 기준 위치 |
|---|---|
| 비전·규칙·기획·결정 | 문서 작업공간 |
| 일정·위험·총괄 보고 | 문서 작업공간 |
| 개발 작업·결함 | GitHub Issue |
| 코드·테스트·배포 | GitHub 저장소 |
| 변경 검토와 테스트 증거 | GitHub Pull Request |

## 역할

### 기획

- 플레이어 가치, 규칙과 수용 기준을 정의합니다.
- 구현 시작 전에 모호한 규칙과 제외 범위를 정리합니다.
- 플레이테스트 결과에 따라 기획 변경을 결정합니다.

### 프로그래머

- Issue와 수용 기준을 기준으로 구현합니다.
- 변경을 테스트하고 PR에 결과와 위험을 기록합니다.
- 기술 제약으로 기획이 바뀌면 관련 역할에 판단을 요청합니다.

### QA

- 수용 기준, 회귀 범위와 공개 웹 환경을 검증합니다.
- 결함은 재현 단계, 기대/실제 결과, 심각도와 증거를 포함해 Issue로 기록합니다.
- 검증하지 못한 범위와 잔여 위험을 명시합니다.

### PM

- 범위, 우선순위, 일정, 의존성과 차단 요소를 관리합니다.
- Issue와 문서 상태를 맞추고 사용자 결정이 필요한 사안을 총괄 보고로 올립니다.

## 업무 흐름

`기획 및 수용 기준 → PM 우선순위 → Issue → 구현 및 PR → QA 검증 → 병합 → 총괄 보고`

## 사용자 결정 요청

사용자 판단이 필요한 사안은 다음 형식을 사용합니다.

- 상황
- 선택지
- 각 선택지의 일정·품질·범위 영향
- 기획·프로그래머·QA·PM 의견
- 권고안
- 결정 필요일
- 근거 문서·Issue·PR 링크

## 총괄 보고

총괄 관리자는 문서 작업공간과 GitHub 상태를 함께 확인하고 다음을 전달합니다.

- 완료 및 진행 중 업무
- 역할별 다음 행동
- 일정·품질·권리·배포 위험
- 차단 요소와 책임 역할
- 사용자 결정이 필요한 내용과 권고안
