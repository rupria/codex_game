# 할리갈리 화면 아트·UI·연출 전달서 0.06

## 확정 기준

- 사용자 확정 원본: `halli_screen_layout_approved_0_06.png`
- 개발용 최종 배치 시안: `halli_screen_layout_central_bells_mock_0_06.png`
- 960×540 개발 기준본: `halli_screen_layout_central_bells_mock_960x540_0_06.png`
- 원본 크기: 1672×941 RGB PNG, 16:9 화면 기준
- 용도: 할리갈리 클로즈업 화면의 구도, 색상, 픽셀 아트 분위기 기준
- 플레이어는 청록색, AI는 붉은색으로 구분한다.
- 시점은 원형 테이블을 내려다보는 3/4 탑다운으로 고정한다.
- 사용자 확정 원본의 분위기와 테이블은 유지하되, 실제 배치는 중앙 벨과 AI 상태 영역이 반영된 개발용 최종 배치 시안을 따른다.
- 두 이미지에 그려진 카드, 벨, HUD 윤곽은 배치 가이드다. 실제 게임에서는 카드·벨·HUD를 분리된 인터랙티브 에셋으로 배치해 중복 표시를 막는다.

## 화면 배치

좌표는 16:9 안전 영역을 기준으로 한 화면 정규화 비율이다. 해상도 변경 시 비율을 유지한다.

| 요소 | 권장 중심 위치 | 표시 규칙 |
| --- | --- | --- |
| 첫 커뮤니티 카드 / 잠긴 카드 | X 50%, Y 21% | 두 슬롯을 상단 중앙에 가로 배치한다. |
| 플레이어 필드 카드 | X 31%, Y 43% | 현재 카드가 가장 위에 보이는 2장 더미다. |
| AI 필드 카드 | X 69%, Y 43% | 현재 카드가 가장 위에 보이는 2장 더미다. |
| 왼쪽 청록 벨 | X 44%, Y 58% | 플레이어 필드 카드 아래쪽에 둔다. |
| 오른쪽 붉은 벨 | X 56%, Y 58% | AI 필드 카드 아래쪽에 둔다. |
| 카드 펼치기 카드 뭉치 | X 50%, Y 70% | 두 벨 아래 중앙에 3장 이상 겹친 뒷면 더미로 표시한다. |
| 플레이어 HP·승수 | 좌측 상단 | 청록 외곽선과 흰색 핵심 정보로 표시한다. |
| AI HP·승수 | 우측 상단 | 붉은 외곽선과 흰색 핵심 정보로 표시한다. |
| 플레이어 획득 카드 | 좌측 하단 | 승리로 획득한 실제 할리갈리 카드 앞면을 최대 3장 표시한다. |
| AI 획득 카드 | 우측 하단 | 카드 뒷면 1장과 보유 장수를 표시한다. |

벨은 테이블 좌우 끝에 두지 않는다. 두 벨 사이에는 화면 너비의 최소 6% 이상 빈 공간을 두며, 실제 클릭 영역은 보이는 벨 크기의 115~125%로 설정한다.

## 입력과 상태 표시

- `Q`: 왼쪽 청록 벨
- `W`: 카드 펼치기 또는 리뷰 계속
- `E`: 오른쪽 붉은 벨
- 할리갈리 진행 중에는 플레이어 조작부만 선명한 청록색으로 표시한다.
- AI 측에는 조작 버튼을 표시하지 않는다. 우측 하단은 `AI 판단 중`, 반응 표시, 획득 카드 수만 보여준다.
- 비활성 요소는 채도를 낮추고 입력 불가 시 잠금 표시를 사용한다.
- 보상 카드 선택 화면에서는 기존 `Q/E 이동, W 선택` 입력을 문맥적으로 재사용하되, 화면 라벨을 해당 선택 조작으로 즉시 변경한다.

## 벨 그래픽 상태

기존 분리 에셋을 사용한다.

- 기본: `Assets/Art/Prototype/UI/bell_idle.png`
- 호버: `Assets/Art/Prototype/UI/bell_hover.png`
- 눌림: `Assets/Art/Prototype/UI/bell_pressed.png`
- 오답: `Assets/Art/Prototype/UI/bell_wrong.png`
- 정답: `bell_pressed.png` 위에 해당 진영 색 외곽광과 짧은 원형 파동을 합성한다.
- 비활성: `bell_idle.png`의 채도 0%, 불투명도 35%로 표시한다.

호버 시 외곽선을 밝게 하고 최대 1.04배까지 확대한다. 눌림은 0.08초 이내로 짧게 수축했다 복귀한다. 오답은 0.15~0.18초 좌우 흔들림과 낮은 채도의 붉은 플래시를 사용한다.
정답 외곽광은 판정이 끝난 뒤에만 표시하며 입력 전에 정답 벨을 암시하지 않는다.

## 연출 타임라인

### 할리갈리 진입

1. 딜러가 첫 커뮤니티 카드 한 장을 화면 중앙에 펼친다.
2. 카드가 1.08배까지 확대된 뒤 상단 중앙 슬롯으로 이동한다. 전체 0.55~0.65초.
3. 잠긴 두 번째 커뮤니티 카드가 0.15초간 약하게 점등된다.
4. 카메라는 0.35~0.45초 동안 할리갈리 클로즈업 구도로 이동한다.
5. 카메라 정착 후 `Q / W / E` 조작 안내를 짧게 표시한다.

### 카드 펼치기

1. `W` 입력 시 카드 더미가 2px 눌린다.
2. 새 카드는 더미에서 필드로 0.18~0.22초 이동하며 앞면으로 전환된다.
3. 카드 문양과 해골 수가 완전히 읽히는 `CardRevealComplete` 시점부터 벨 판정 시간을 시작한다.
4. 카드 이동 중에는 추가 `W` 입력을 막고, `Q/E`는 판정 시작 전까지 비활성으로 표시한다.
5. 중앙 하단 더미는 남은 카드가 있는 동안 항상 2~3장의 뒷면 가장자리가 보이게 해 단일 카드나 버튼으로 오해되지 않게 한다.

### 벨 판정

1. 입력한 벨은 즉시 눌림 상태로 바뀐다.
2. 정답이면 대응하는 필드 카드와 벨을 청록 또는 붉은색으로 0.15초 강조한다.
3. 오답이면 벨의 오답 상태와 해당 필드의 짧은 흔들림을 표시한다.
4. 입력 판정 결과와 시각 피드백 사이에 인위적인 지연을 넣지 않는다.

### 카드 획득

1. 획득 대상 카드가 0.08초간 강조된다.
2. 필드에서 획득 보관 영역까지 0.35~0.45초 곡선 이동한다.
3. 플레이어가 판정에서 승리하면 획득한 실제 카드 앞면을 좌측 하단 트레이에 최대 3장 쌓는다.
4. AI 획득 카드는 판정 직후 앞면을 0.6~0.8초 보여준 뒤 0.16초 동안 뒷면으로 전환한다.
5. 카드 이동이 끝나는 시점에 AI 보유 장수 또는 플레이어 획득 슬롯을 갱신한다.
6. `카드 획득` 텍스트만 표시하는 방식은 사용하지 않는다.
7. 플레이어 획득 카드는 다음 플립 이후에도 숨기지 않고 할리갈리 단계가 끝날 때까지 계속 확인할 수 있게 한다.

### 포커 단계 전환

1. 할리갈리 종료 후 추가 벨 입력을 즉시 막는다.
2. 필드 카드와 벨 UI의 채도를 0.2~0.3초 동안 낮춘다.
3. 획득 카드가 포커 손패 위치로 0.4~0.6초 재배치된다.
4. 카메라는 0.55~0.7초 동안 포커 와이드 구도로 줌아웃한다.
5. 자유 카메라는 사용하지 않고 `할리갈리 클로즈업`과 `포커 와이드` 두 구도만 전환한다.

### 최초 실행 화면

1. 조작 버튼은 `START`와 `GUIDE`만 표시한다.
2. 개발 상태, 에셋 이름과 긴 규칙 설명은 공개 화면에 표시하지 않는다.
3. `GUIDE`는 `카드 펼치기 → 같은 문양의 해골 합 확인 → 대응 벨 누르기 → 획득 카드로 포커 진행` 순서를 이미지 중심으로 안내한다.
4. 첫 플레이 중에는 현재 필요한 조작만 짧게 노출하고 행동 완료 후 숨긴다.

## 가시성 우선순위

1. 현재 펼쳐진 좌우 카드
2. 중앙의 벨 2개
3. 카드 펼치기 버튼
4. 카드 문양과 해골 수
5. 획득 카드
6. 현재 승수와 HP
7. 커뮤니티 카드와 잠긴 카드
8. 아이템 및 AI 상태

## 개발 연결 범위

- 현재 `Assets/Art/Prototype/Board/board_layout_wip.png`는 기존 포커 와이드 배경이다. 할리갈리 단계에서는 이 문서의 확정 레퍼런스를 기준으로 별도 클로즈업 구도를 구성한다.
- 카드, 벨, HUD, 획득 슬롯은 정적 배경에 굽지 않고 개별 UI 레이어로 연결한다.
- 기존 스냅샷의 `PlayerAcquiredCount`, `AiAcquiredCount`, `LastAcquiredCards`를 획득 UI와 이동 연출에 사용한다.
- 카메라 전환, 입력 라우팅, 판정 시점 연결과 카드 이동 애니메이션은 프로그래머 담당이다.
- 아트 담당 범위는 확정 레퍼런스, 분리 에셋의 시각 규격, 상태별 연출 명세 제공까지다.
- 960×540 기준 시안을 원본 비율로 확대해 1280×720과 1920×1080에서도 핵심 정보가 안전 영역 안에 유지되게 한다.

## 출처와 사용 기록

- 사용자 확정 원본은 이 작업에서 제공된 프로젝트 내부 레퍼런스다.
- 중앙 벨 개발 시안은 2026-08-07 OpenAI 내장 ImageGen 편집 모드로 제작했다.
- 편집 프롬프트는 원본의 테이블·팔레트·HUD·필드 카드 구도를 보존하고, 좌우 끝 벨을 중앙으로 이동하며, 중앙 하단 카드 뭉치, 승리 후 앞면 획득 카드 트레이와 우하단 AI 상태 영역을 구성하도록 지정했다.
- 외부 무료·유료 에셋 팩은 추가하지 않았다.
- 공개 빌드 사용 전 프로젝트의 최종 라이선스·권리 검토 절차를 따른다.

## 완료 조건

- 첫 진입만 보아도 `W로 펼치기 → 조건 확인 → Q/E 벨 선택 → 카드 획득` 흐름을 이해할 수 있다.
- 좌우 카드와 중앙 벨이 HUD보다 먼저 보인다.
- 벨 호버·눌림·오답 상태가 즉시 구분된다.
- 획득 카드의 출발점과 도착점이 시각적으로 이어진다.
- 할리갈리 진행 중 중앙 하단 카드 뭉치와 승리로 획득한 플레이어 카드가 계속 보인다.
- 할리갈리와 포커의 카메라 구도가 명확히 다르며 전환 중 어지러운 자유 이동이 없다.
- 최초 실행 화면에는 `START`와 `GUIDE` 외의 조작 버튼이 없다.
