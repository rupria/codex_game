## 2. 구현 목표

처음 보는 플레이어가 설명 없이 다음 네 가지를 화면에서 이해하게 한다.

1. 지금 할리갈리 단계가 진행 중이다.
2. 중앙 카드를 펼친 뒤 두 벨 중 하나를 선택한다.
3. 판정 결과로 어떤 카드를 누가 획득했는지 확인한다.
4. 할리갈리가 끝나면 포커 단계로 전환된다.

## 3. 필수 구현 범위

### A. 최초 실행 화면

- 공개 시작 화면의 조작 버튼은 `START`와 `GUIDE`만 남긴다.
- 게임 로고·제목과 배경 장식은 표시할 수 있다.
- 개발 빌드명, 에셋 로드 상태, 긴 목표·조작 설명은 제거한다.
- `GUIDE`는 별도 세션을 시작하지 않는 오버레이로 구현한다.
- 가이드에는 `카드 펼치기 → 같은 문양 해골 합 3 판정 → 벨 선택 → 획득 카드로 포커 승패 예측`을 이미지 중심으로 표시한다.
- `START`를 누르기 전에는 게임 타이머를 시작하지 않는다.

### B. 첫 커뮤니티 카드 공개

- `START` 후 딜러가 첫 커뮤니티 카드 한 장을 펼치는 연출을 재생한다.
- 카드를 잠시 확대하고 상단 중앙의 첫 커뮤니티 카드 슬롯에 고정한다.
- 옆에는 잠긴 두 번째 커뮤니티 카드 슬롯을 항상 표시한다.
- 공개 연출 중에는 펼치기와 벨 입력을 잠근다.
- 할리갈리 30초 입력 제한은 조작 가능 상태가 된 뒤 시작하거나, 연출 시간을 제한 시간에서 제외한다.
- 시작부터 할리갈리 조작 가능 상태까지 3초 이내를 목표로 한다.

### C. 할리갈리 화면 배치

- 기준 해상도는 `960×540`, 화면은 3/4 탑다운 구도다.
- 플레이어는 청록색, AI는 붉은색으로 구분한다.
- 상단 중앙: 첫 커뮤니티 카드와 잠긴 두 번째 카드
- 좌측 중앙: 왼쪽 필드 카드
- 우측 중앙: 오른쪽 필드 카드
- 중앙: 왼쪽 청록 벨과 오른쪽 붉은 벨
- 두 벨 아래 중앙: 카드 펼치기 버튼 또는 카드 더미
- 상단 좌우: 플레이어·AI HP와 할리갈리 승수
- 하단 좌우: 플레이어 획득 카드·아이템과 AI 획득 상태

### D. 마우스·키보드 입력

- 벨을 테이블 양 끝에 두지 않고 중앙에 나란히 배치한다.
- 왼쪽 벨은 왼쪽 필드, 오른쪽 벨은 오른쪽 필드 판정이다.
- 기준 해상도 1차 권장값은 벨 시각 크기 `64~72 px`, 클릭 영역 `88~96 px`다.
- 두 벨 클릭 영역 사이에 최소 `24 px` 간격을 둔다.
- 카드 펼치기 클릭 영역은 두 벨 아래에 두고 벨 클릭 영역과 겹치지 않게 한다.
- 마우스와 키보드를 동시에 지원한다.
- 키보드 기준은 `Q = 왼쪽 벨`, `W = 카드 펼치기`, `E = 오른쪽 벨`이다.
- 현재 구현의 방향키·스페이스 입력은 보조 입력으로 유지할 수 있지만 화면 가이드의 기본 표기는 `Q/W/E`로 통일한다.
- 입력 잠금 상태에서는 버튼의 비활성 표현과 실제 입력 차단이 일치해야 한다.

### E. 획득 카드 표시

- 플레이어 획득 후보 카드는 좌측 하단 트레이에 앞면으로 계속 표시한다.
- 획득 순간에는 필드 카드가 플레이어 트레이로 이동하는 `0.35~0.55초` 연출을 사용한다.
- 획득 연출은 0.08의 판정 후 리뷰 시간 안에서 처리하며 다음 입력 가능 시점을 임의로 늦추지 않는다.
- AI 획득 카드는 판정 직후 앞면을 잠시 보여준 뒤 우측 하단에 뒷면과 장수로 표시한다.
- AI의 전체 후보 앞면은 지속적으로 공개하지 않는다.
- 단순한 마지막 획득 텍스트만으로 완료 처리하지 않는다.

### F. 할리갈리에서 포커로 전환

- 할리갈리 종료 시 벨과 필드 입력을 잠근다.
- 필드와 벨 UI를 정리하면서 테이블을 와이드 구도로 줌아웃한다.
- 획득 후보 카드를 포커 선택·손패 영역으로 재배치한다.
- `0.8~1.2초` 내에 포커 진입 구도를 보여준다.
- 전환 완료 후 다음 게임 상태로 한 번만 진행한다. 중복 클릭이나 중복 `Advance`가 발생하지 않아야 한다.
- 할리갈리 입력 UI는 포커 단계에서 보이거나 클릭되지 않아야 한다.
- 자유 카메라 대신 `할리갈리 클로즈업`과 `포커 와이드` 두 프리셋만 사용한다.

### G. AI 영역

- AI 측에 플레이어와 같은 조작 버튼을 표시하지 않는다.
- `AI 판단 중`, 반응 상태와 획득 카드 수를 표시하는 상태 영역으로 사용한다.
- AI의 실제 반응 시각이나 정답 벨을 미리 노출하지 않는다.

## 4. 화면 상태와 입력 허용표

| 화면 상태 | 표시 | 허용 입력 |
|---|---|---|
| 시작 화면 | 로고, `START`, `GUIDE` | 시작, 가이드 열기 |
| 가이드 | 핵심 행동 안내 | 닫기 |
| 첫 카드 공개 | 딜러·커뮤니티 카드 연출 | 입력 잠금 |
| 할리갈리 준비 | 필드, 중앙 벨, 펼치기 | `W`·마우스 펼치기, 유효 상태의 `Q/E`·마우스 벨 |
| 벨 판정·획득 리뷰 | 결과와 카드 이동 | 다음 판정에 영향을 주는 입력 잠금 |
| 할리갈리 종료 전환 | 정리·줌아웃 | 입력 잠금 |
| 개인 카드·포커 | 획득 카드, 공용 카드, 포커 UI | 해당 단계 입력만 허용 |

## 5. 현재 구현에서 확인할 지점

다음은 구현 위치를 강제하는 요구가 아니라 현재 `dev` 구조에서의 확인 지점이다.

- `PlayableDevView.DrawIntro()` — `START`·`GUIDE` 시작 화면
- `PlayableDevView.HandleHalliInput()` — `Q/W/E`와 기존 보조 키 입력
- `HalliDevPanel.Draw()`·`DrawActions()` — 필드, 중앙 벨과 펼치기 배치
- `PrototypeHalliSnapshot` — 현재 획득 장수와 마지막 획득 카드만 제공하므로 지속 트레이에 필요한 누적 카드 읽기 모델 확인
- `PlayableGamePhase` 전환 — 첫 카드 공개와 할리갈리 종료 연출을 게임 규칙 상태와 분리할지 검토
- `PlayableDevView.OnGUI()` — 현재 기준 좌표가 `960×600` 스케일과 `960×540` 보드를 함께 사용하므로 기준 화면을 `960×540` 안전 영역으로 통일할지 확인

표현 전용 연출 때문에 코어 판정 상태를 불필요하게 늘리지 않아도 된다. 다만 연출 중에도 게임 타이머가 감소하거나 입력이 세션에 전달되는 문제는 없어야 한다.

## 6. 권장 작업 순서

1. 시작 화면을 `START`·`GUIDE` 구조로 정리한다.
2. `960×540` 기준 할리갈리 고정 배치를 만든다.
3. 중앙 벨 2개와 펼치기 버튼의 마우스·`Q/W/E` 입력을 연결한다.
4. 누적 획득 카드 읽기 모델과 플레이어·AI 트레이를 연결한다.
5. 첫 커뮤니티 카드 공개와 할리갈리 클로즈업을 연결한다.
6. 할리갈리 종료 후 포커 와이드 전환을 연결한다.
7. 화면 크기, 입력 잠금, 타이머와 중복 진행을 회귀 검증한다.
