# QA 개발 치트 사용 가이드 0.1.2

## 적용 범위

- 대상: `0.1.2` WebGL dev/QA 미리보기 빌드
- 진입 조건: `ENABLE_GAMEPLAY_CHEATS`가 포함된 개발 빌드에서만 활성화
- 일반 공개·`pub` 빌드: 치트 코드와 UI를 조건부 컴파일에서 제외
- 용도: 스테이지·아이템·포커 상태를 빠르게 재현하기 위한 QA 보조 수단

## 열기와 닫기

1. 게임 화면을 한 번 클릭하여 키보드 포커스를 둔다.
2. `F10`을 눌러 `DEVELOPMENT CHEATS` 패널을 연다.
3. 패널 우측 상단 `CLOSE` 또는 다시 `F10`을 눌러 닫는다.
4. 패널이 열려 있는 동안 일반 게임 입력은 차단된다.

## 제공 명령

### COMPLETE STAGE

- 현재 전투가 진행 중일 때 AI HP를 0으로 만들고 스테이지 승리·보상 정산 화면으로 이동한다.
- 인트로, 이미 끝난 전투 등 비활성 상태에서는 `rejected:inactive`로 기록된다.
- 권장 확인: 스테이지 클리어 → 총알 정산 → 바 상점 → 다음 스테이지 전환.

### GRANT UNIQUE ITEM

- `Reload`, `BottomDeal`, `HypeMan`, `HealthRecovery` 중 하나를 인벤토리에 지급한다.
- 동일 `ItemId` 중복 또는 4칸 초과는 거부되며 결과가 명령 기록에 남는다.
- 권장 확인: 포커 전 아이템 상자 열기 → 4칸 표시 → 아이템 사용·소모 → 패 확정.

### SET EXACT POKER HAND

- 현재 전투 중 포커 상태를 지정 프리셋으로 교체하고 예측 단계로 이동한다.
- 프리셋: `NoPair`, `OnePair`, `TwoPair`, `ThreeOfAKind`, `AceLowStraight`, `AceHighStraight`, `Flush`, `FullHouse`, `FourOfAKind`, `StraightFlush`, `RoyalStraightFlush`, `PlayerJoker`, `AiJoker`, `SuitTieBoundary`.
- 비활성 전투나 잘못된 카드 구성은 `rejected:shape` 또는 `rejected:cards`로 기록된다.
- 권장 확인: 승패 버튼 → 결과 라벨 → 예측 성공·실패 → HP·보상 반영.

## 치트 사용 표식과 기록

- 치트를 한 번이라도 실행하면 화면 우측 상단에 `CHEAT / QA` 표식이 나타난다.
- 패널에는 최근 명령 4개가 보이며 내부 기록은 최대 20개를 유지한다.
- 기록 형식: `command input -> result`.
- 새 게임 세션을 시작하면 치트 사용 표식과 명령 기록이 초기화된다.

## QA 전달 기록 권장 형식

- 빌드명 / 전체 Git SHA / 플레이 링크
- 브라우저·OS / 확인 시각
- 실행한 치트 명령과 패널에 표시된 결과
- 기대 상태와 실제 상태
- 재현 영상 또는 화면 캡처
- 치트 사용 빌드에서 발견한 현상인지 일반 플레이에서도 재현되는지 구분

## 제한

- 치트는 상태 재현을 단축할 뿐 정상 플레이 흐름의 최종 QA 판정을 대신하지 않는다.
- `COMPLETE STAGE`는 중간 전투 규칙을 생략하므로 전투 과정 검증에는 사용하지 않는다.
- 포커 프리셋은 카드 판정·결과 UI 확인용이며 일반 분배 확률 검증에는 사용하지 않는다.
- 이번 개발 빌드의 화면 품질·게임 규칙 최종 합격 여부는 QA 담당이 별도로 판정한다.
