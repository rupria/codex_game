# 이슈 #49 스테이지 보상 팝업 아트 인계 — StageReward 0.5.5

## 확인된 재발 원인

`PlayableDevView.DrawStageWon()`에서 기존 스테이지 클리어 화면을 먼저 그린 뒤 반투명 보상 팝업을 겹쳐 그리고 있다. 이 때문에 이전 클리어 프레임의 큰 원형 표식이 새 보상 영역 아래로 비치며, `Continue` 버튼도 팝업 바깥에 별도 배치되어 하나의 화면처럼 보이지 않는다.

## 개선 방향

- 960×540 기준 중앙 `(140, 90, 680, 360)`의 단일 불투명 팝업으로 통합한다.
- 제목, 보상 2×2 그리드, 계속 버튼을 모두 팝업 내부 안전 영역에 둔다.
- 보상 행은 콘텐츠 영역에서만 렌더링하고 반드시 클리핑한다.
- 4개를 초과하는 보상은 내부 페이지 또는 스크롤로 처리한다. 팝업 프레임을 확장하거나 바깥에 그리지 않는다.

## 프로그래머 연결 작업

1. `PlayableDevView.DrawStageWon()`에서 보상 팝업 아래에 남는 `_presentation0124Panel.DrawStageClear()` 중복 렌더를 제거한다.
2. `StageReward_0_5_4` 바인딩을 `StageReward_0_5_5`로 교체한다.
3. 보상 콘텐츠 그룹을 팝업 로컬 `(24, 88, 632, 154)`로 제한하고 하드 클립한다.
4. 행 크기를 304×64, 열 간격 24, 행 간격 12로 적용한다.
5. `Continue` 버튼을 팝업 로컬 `(220, 288, 240, 52)` 안으로 이동한다. 버튼 클릭·키보드 진행 로직은 유지한다.
6. 재화 계산, 보상 개수, 저장 순서와 게임 플로우는 변경하지 않는다.

## 검수 조건

- 보상 팝업 뒤로 기존 스테이지 클리어 표식이나 패널이 비치지 않는다.
- 보상 행·텍스트·아이콘·계속 버튼이 팝업 테두리를 넘지 않는다.
- 960×540, 1280×720, 1920×1080에서 동일한 중앙 정렬과 안전 여백을 유지한다.
- 한국어·영어의 긴 보상 이름은 행 내부에서 말줄임 또는 축소 처리하고 인접 행을 침범하지 않는다.
- 0개, 1개, 4개, 5개 이상 보상 상태를 각각 확인한다.
- 팝업이 열린 동안 뒤쪽 클릭 입력은 차단한다.
