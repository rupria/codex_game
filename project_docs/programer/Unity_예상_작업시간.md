# Unity 이용 시 예상 작업시간

- 역할: 프로그래머
- 작성일: 2026-08-06
- 기준 기획: `designer/게임진행플로우_0.01.md`
- 기준 엔진: Unity 6.3 LTS, C#, URP
- 대상: 서버 없는 싱글 플레이, Web 우선, Windows x86_64 빌드 준비
- 상태: 기획 P0 미확정 상태의 1차 추정치
- Git 정책: 사용자 승인 전 커밋·푸시하지 않음

## 1. 요약

프로그래머 1명이 전담하고 기본 UI·카드·3D 에셋이 제공된다는 가정에서 예상 일정은 다음과 같다.

| 산출 단계 | 예상 시간 | 예상 작업일 |
|---|---:|---:|
| Unity Web 기술 스파이크 | 12~20시간 | 1.5~2.5일 |
| 코어 플레이 가능 프로토타입 | 누적 64~88시간 | 누적 8~11일 |
| 현재 게임 흐름 전체 구현 | 누적 104~144시간 | 누적 13~18일 |
| 제출 후보 안정화 빌드 | 누적 136~184시간 | 누적 17~23일 |

1일 8시간 기준이며 회의, 기획 대기, 에셋 제작과 QA 재검증 대기 시간은 제외한 순수 프로그래머 작업량이다. 실제 달력 일정은 역할 간 피드백과 병행 작업 때문에 늘어날 수 있다.

현재 목표의 현실적인 기준은 다음과 같다.

- 최소 플레이 가능 버전: 약 2주
- 현재 흐름 전체와 기본 3D 연출: 약 3주
- Web 공개 링크와 Windows 빌드까지 안정화: 약 3~4주

## 2. 산정 전제

- 프로그래머 1명이 Unity와 C#의 기본 사용법을 알고 있다.
- Unity 6.3 LTS 버전을 팀 공통 버전으로 고정한다.
- 서버, 로그인, 온라인 대전과 클라우드 저장을 구현하지 않는다.
- 카드 규칙과 포커 판정은 코드 기반 상태 머신으로 구현한다.
- 3D 물리는 카드 펼치기, 카드 이동과 벨 연출에만 사용한다.
- 승패, 타이머와 획득 판정은 물리 결과에 의존하지 않는다.
- 카드 이미지, UI 디자인과 3D 모델은 임시 에셋을 먼저 사용한다.
- 아이템은 초기 1~3종 이내로 제한한다.
- 주요 검증 브라우저는 Chrome/Edge와 Firefox다.
- 모바일 Web은 최초 제출 필수 범위에서 제외하고 별도 결정한다.
- QA의 정식 PASS 시간은 프로그래머 작업시간에 포함하지 않는다.

## 3. 세부 예상시간

| 작업 | 예상 시간 | 주요 산출물 |
|---|---:|---|
| Unity 프로젝트 및 Git 설정 | 4~6시간 | Unity 프로젝트, URP, `.gitignore`, 폴더 구조 |
| Web·Windows 기술 스파이크 | 8~14시간 | Web 테스트 빌드, Windows 테스트 빌드, 3D 물리·입력 확인 |
| 상태 머신과 입력 구조 | 8~12시간 | 게임 상태 전환, `Q-W-E`, 마우스 입력 라우터 |
| 카드 덱과 데이터 모델 | 6~10시간 | 52장 덱, 셔플, 사용 카드와 획득 카드 추적 |

| AI 벨 경쟁과 타이머 | 10~16시간 | AI 반응 예약, 시간 제한, 입력 우선순위 |
| 3승 및 개인 카드 정리 | 8~12시간 | 3승 종료, 3장 선택·무작위 보충 |
| 공용 카드·패 확정·쇼다운 | 8~12시간 | 공용 카드 2장, AI 공개, 최종 결과 화면 |
| 아이템·HP·스테이지 | 12~20시간 | 아이템 창, 피해, 보상, 반복·종료 분기 |
| UI와 첫 화면 가이드 | 12~18시간 | 메뉴, 조작 안내, 상태 표시, 반응형 UI |
| 3D 카드·벨 기본 연출 | 16~24시간 | 카드 뒤집기·이동, 벨 충돌, 실패 복구 처리 |
| Web 최적화·공개 링크 준비 | 10~16시간 | 로딩 최적화, 압축, 브라우저 오류 대응 |
| Windows x86_64 빌드 | 4~8시간 | 실행 파일, 실행 확인, 빌드 절차 |

세부 작업을 모두 단순 합산하면 142~214시간이지만 일부 UI, 상태 머신, 연출과 검증은 동시에 진행할 수 있다. 따라서 중복 작업을 제거한 전체 예상치는 136~184시간으로 잡는다.

## 4. 단계별 산출물

### 1단계 - 기술 스파이크

예상: 1.5~2.5일

- Unity 6.3 LTS Web 빌드 실행
- Windows x86_64 빌드 실행
- `Q-W-E`와 마우스 입력 확인
- 3D 카드 10~20장과 벨 물리 연출 반복
- 브라우저별 초기 로딩 시간과 오류 기록

이 단계에서 Web 빌드가 안정적으로 동작하지 않으면 Unity 채택 여부를 다시 판단한다.

### 2단계 - 코어 플레이 프로토타입

예상 누적: 8~11일

- 게임 시작부터 할리갈리 3승까지 진행
- 좌우 카드 펼치기와 합계 3 판정
- 오조작과 AI 반응의 임시 규칙
- 개인 카드 3장 구성
- 공용 카드와 기본 5장 포커 쇼다운
- 결과 확인과 즉시 다시 시작

아이템, HP, 다중 스테이지와 고급 연출은 이 단계에서 제외할 수 있다.

### 3단계 - 현재 흐름 전체 구현

예상 누적: 13~18일

- 제한 시간과 최대 26회 예외
- 카드 선택·보충과 AI 카드 정리
- 아이템 사용 창과 패 확정
- HP 피해, 보상과 다음 스테이지 분기
- 기본 3D 카드와 벨 연출
- 첫 화면 게임 가이드와 전체 UI 연결

### 4단계 - 제출 후보 안정화

예상 누적: 17~23일

- Web 로딩 크기와 메모리 최적화
- 공개 HTTPS 환경 검증
- Chrome/Edge·Firefox 반복 테스트
- 시크릿 창과 새 캐시에서 첫 플레이 확인
- Windows x86_64 실행 파일 확인
- 치명 결함 수정과 빌드 절차 문서화

`pub` 반영과 최종 공개 URL 갱신은 사용자의 별도 승인 이후 진행한다.

## 5. 일정 변동 요인

| 조건 | 추가 예상시간 |
|---|---:|
| 담당자가 Unity 초보 | 전체 일정의 30~60% 증가 |
| 3D 모델과 애니메이션을 프로그래머가 직접 제작 | 3~7일 증가 |
| 모바일 Web 정식 지원 | 2~5일 증가 |
| 아이템 3종 초과 | 1종당 4~8시간 증가 |
| 저장·성장 시스템 추가 | 2~4일 증가 |
| 고급 셰이더·후처리 연출 | 2~5일 증가 |
| 기획 P0가 구현 중 변경 | 변경 1회당 1~3일 증가 가능 |
| 외부 에셋 라이선스 재검토·교체 | 0.5~2일 증가 |

반대로 카드·UI·3D 에셋과 확정 기획이 구현 시작 전에 제공되면 전체 일정에서 약 2~4일을 줄일 수 있다.

## 6. 일정 확정 전에 필요한 기획 결정

다음 항목이 확정돼야 오차를 약 ±15% 안으로 줄일 수 있다.

- 제한 시간과 시간 초과 처리
- 오조작 페널티
- AI와 플레이어 동시 입력 처리
- 벨 승리 시 획득 카드 범위
- 26회 제한 도달 처리
- 포커 동률 처리
- 아이템 종류와 초기 개수
- HP와 피해량
- 모바일 Web 지원 여부와 최소 해상도
- 3D 물리가 단순 연출인지 핵심 조작인지

## 7. 권장 일정 운영

1. 먼저 2일 내외의 Unity Web 기술 스파이크를 진행한다.
2. 기술 스파이크 통과 후 코어 플레이 프로토타입을 약 2주 안에 만든다.
3. 코어 재미를 플레이테스트한 뒤 아이템, HP와 연출 범위를 고정한다.
4. 마지막 1주 이상을 Web 최적화, 공개 링크와 회귀 수정에 확보한다.

제출 안정성을 위해 전체 기간이 3주 미만이면 아이템·스테이지·고급 3D 연출을 축소하고 코어 플레이와 Web 공개 링크를 우선하는 것이 안전하다.

## 8. 추정 정확도

- 현재 추정 신뢰도: 낮음~보통
- 예상 오차: 약 -20%~+40%
- 오차 원인: 기획 P0 미확정, 에셋 준비 상태 미확인, Unity 숙련도 미확인, 3D 연출 수준 미확정

기술 스파이크와 기획 P0 결정이 완료되면 실제 작업 목록을 기준으로 다시 산정한다.
