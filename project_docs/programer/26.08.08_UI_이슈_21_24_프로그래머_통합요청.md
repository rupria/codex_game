## 3. 현재 코드 확인 결과

### #21 가이드

- `GuideModalPanel.cs`가 아트 텍스처를 그린 뒤 `GUI.Label`로 페이지 번호와 이전·다음·닫기 텍스트를 다시 표시한다.
- 같은 사각형에 투명 `GUI.Button`이 추가돼 아트의 아이콘과 실제 클릭 영역이 구분되지 않는다.
- `GuideModalState`와 ESC·좌우 키 동작은 이미 있으므로 상태 로직보다 렌더링·히트 영역 정리가 핵심이다.

### #22 메인 버튼

- `PlayableDevView.DrawIntro()`가 큰 기본 `GUI.Box` 안에 기본 `GUI.Button` 두 개를 직접 배치한다.
- START와 GUIDE의 동작 이벤트는 이미 분리돼 있으나, 최종 아트 프레임과 기본 IMGUI 배경·텍스트가 겹칠 수 있다.

### #23 HP

- 현재 HP는 `PlayableGameSnapshot.Health`에서 플레이어·AI 각각 전달된다.
- 현재 최대 HP는 `GameRules.StartingHealth = 3`이고 `BattleHealth`도 0~3 범위를 보장한다.
- `HalliDevPanel.DrawScoreboard()`는 HP를 현지화 텍스트 안에만 표시한다.

### #24 타이머

- `PrototypeHalliSnapshot.RemainingMicroseconds`가 현재 UI 숫자 초의 단일 시간원이다.
- 같은 값이 30초 벨 입력 제한뿐 아니라 결과 후 2초 Review 잠금의 남은 시간에도 사용된다.
- 밧줄 진행은 `RemainingMicroseconds`만 보고 그리면 안 되고, `CanRing`과 세션 Phase를 함께 확인해야 한다.
- 기존 시간 초과 판정은 세션이 담당하므로 Presentation에서 두 번째 패배·승수 처리를 만들지 않는다.

## 4. 구현 요청

### 4.1 #21 가이드 아이콘 내비게이션

1. 가이드 하단의 회색 텍스트형 이전·다음·닫기와 별도 페이지 번호 박스를 제거한다.
2. 아트에 포함된 이전·다음·닫기 아이콘의 보이는 경계와 동일한 히트 영역을 둔다.
3. 아이콘 위에 동일한 의미의 `GUI.Label` 또는 기본 `GUI.Button` 배경을 다시 그리지 않는다.
4. 이전·다음은 `GuideModalState.MovePrevious/MoveNext`, 닫기는 `Close`에 각각 한 번만 연결한다.
5. 1쪽 이전과 4쪽 다음은 경계를 넘지 않으며 비활성 외형과 실제 입력 상태를 일치시킨다.
6. ESC 닫기와 가이드 중 전투 입력·타이머 차단은 기존 동작을 보존한다.

권장 테스트:

- `GuideModalStateTests`의 1↔4 경계·열기·닫기 회귀
- 아이콘 클릭 1회당 페이지 이동 또는 닫기 1회
- 가이드 열림 중 `StartRequested`·전투 입력 미발생

### 4.2 #22 START·GUIDE 버튼

1. START와 GUIDE에 공통 버튼 그리기·히트 영역 함수를 사용한다.
2. 외곽 프레임, 내부 배경, 라벨과 실제 클릭 영역을 하나의 Rect 기준으로 계산한다.
3. 아트 버튼 위에 기본 IMGUI 버튼 배경이나 잔여 텍스트를 중복 표시하지 않는다.
4. hover·pressed·disabled 상태를 같은 경계 안에서 전환한다.
5. START 클릭은 `StartRequested` 한 번, GUIDE 클릭은 `_guide.Open()` 한 번만 실행한다.
6. 한국어·English 전환 후에도 라벨 중앙 정렬과 버튼·하단 안내 사이 여백을 유지한다.

권장 테스트:

- 공통 레이아웃 값을 순수 Rect 계산으로 분리한 뒤 두 버튼 크기·간격·히트 영역 테스트
- START/GUIDE 클릭 1회당 이벤트 1회
- 두 언어 라벨의 잘림·겹침 WebGL 시각 확인

### 4.3 #23 HP 하트

1. 플레이어·AI 영역에 각각 최대 HP 수만큼 하트 슬롯을 그린다.
2. 현재 HP만큼 채운 하트, 잃은 HP만큼 빈 하트 또는 어두운 하트를 표시한다.
3. 현재 최대 HP는 `GameRules.StartingHealth`를 사용하고 표시 계층에 숫자 3을 별도 하드코딩하지 않는다.
4. 참가자 라벨·위치를 유지하고 채움·외곽선·명도 차이로 색각 의존을 줄인다.
5. 포커 피해 확정 직후 Snapshot의 HP와 같은 프레임에 갱신한다.
6. 기존 HP 텍스트를 보조로 유지하면 하트 수와 수치가 항상 같아야 한다.
7. 새 게임·스테이지 전환 시 현재 게임 규칙의 초기 HP를 표시한다.

아트 의존:

- 채운 하트·빈 하트 최종 에셋이 없으면 ArtSet 주입 지점과 임시 fallback을 분리한다.
- 트럼프 하트 문양을 HP 아이콘으로 그대로 재사용하지 말고 최종 HUD 에셋 교체가 가능해야 한다.

권장 테스트:

- HP 0·1·2·3의 채운/빈 하트 개수
- 패자만 1칸 감소하고 승자는 유지
- Snapshot HP와 표시 상태 일치

### 4.4 #24 30초 밧줄 타이머

1. 숫자 초와 밧줄 길이는 `PrototypeHalliSnapshot.RemainingMicroseconds` 하나를 사용한다.
2. 정규화 진행값은 `Clamp01(remaining / BellInputTimeout)`으로 계산하고 역행·음수를 방지한다.
3. 밧줄은 30초 벨 입력 제한이 활성인 상태에서만 진행한다.
   - 활성 후보: `CanRing == true`이면서 `ReadyToFlip`, `SequentialReveal`, `BellOpen`
   - 비활성: GUIDE, Intro·전환, Finished, 결과 후 2초 Review 잠금
4. Review의 2초 남은 값을 30초 밧줄로 표시하지 않는다. 잠금 중에는 밧줄·숫자를 숨기거나 정지 상태로 표시한다.
5. 30~11초 일반, 10~1초 긴급 상태를 색상 외에 불꽃 크기·흔들림·형태로 구분한다.
6. 0초 폭발은 라운드당 한 번만 재생한다. 기존 세션의 시간 초과 처리도 한 번만 호출되도록 Presentation에서 별도 승패를 만들지 않는다.
7. 0초와 벨 입력 경합은 기존 코어 판정 순서를 보존하고 결과·승수·폭발을 중복 처리하지 않는다.
8. 새 할리갈리 라운드에서 밧줄 길이·불꽃·폭발 latch를 초기화한다.

구조 권장:

- 남은 비율·표시 초·일반/긴급/폭발/정지 상태를 계산하는 순수 `RopeTimerViewState`를 분리한다.
- 폭발 1회 재생 여부는 프레임마다 0초인지 검사하는 대신 라운드 또는 timeout 전이 식별자에 묶는다.
- 최종 밧줄·불꽃·폭발 에셋은 ArtSet으로 주입하고, 상태 테스트는 에셋 없이 수행할 수 있게 한다.

권장 테스트:

- 30초·11초·10초·1초·0초 경계
- 일시정지·Review 중 진행값 고정 또는 비표시
- 0초 폭발 1회와 시간 초과 1회
- 새 라운드 초기화
- 0초·벨 입력 경합에서 결과 1개

### 4.5 #19 연계 — 대면형 카드 제출 연출

1. 플레이어 덱은 화면 하단 중앙, AI 덱은 화면 상단 중앙에 둔다.
2. 플레이어 카드는 아래에서 위로, AI 카드는 위에서 아래로 판정 슬롯에 이동한다.
3. `덱에서 한 장 분리 → 이동 → 앞면 전환 → 슬롯 고정` 과정이 보여야 한다.
4. 카드가 판정 위치에서 갑자기 생성되거나 같은 중앙 덱에서 양측 카드가 모두 나오지 않게 한다.
5. D-006의 공개 순서와 D-005의 앞면 전환 완료 판정 시점은 변경하지 않는다.
6. 검토 이미지의 흰 영역은 실제 런타임에서 살룬·테이블 배경으로 채운다.

세부 기준은 Drive 원본의 `대면형 덱 배치와 카드 제출 연출`을 따른다.

## 5. 공통 비기능 기준

- `960×540`, `1280×720`, `1920×1080`에서 겹침·잘림·클릭 영역 불일치가 없어야 한다.
- 가이드·버튼·하트·밧줄은 한국어와 영어에서 같은 상태·배치를 유지한다.
- 색상만으로 상태를 전달하지 않는다.
- UI 연출 때문에 카드·벨·상태 문구의 판독과 클릭이 가려지지 않아야 한다.
- Core의 카드 판정, HP 피해, 30초 시간 초과와 승수 규칙을 변경하지 않는다.
- 최종 ArtSet 에셋이 없더라도 상태·입력·테스트 구현과 아트 주입 경계를 먼저 완료할 수 있어야 한다.
