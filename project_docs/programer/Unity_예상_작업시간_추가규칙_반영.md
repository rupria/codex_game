# Unity 예상 작업시간 - 추가 업무환경 규칙 반영

- 역할: 프로그래머
- 작성일: 2026-08-06
- 연결 문서: [Unity_예상_작업시간.md](Unity_예상_작업시간.md)
- 규칙 근거: `codex_game_Git_Drive_업무환경_적용보고서_2026-08-06.pdf`
- 상태: Git-Drive 분리 운영 및 향후 규칙 갱신 가능성 반영
- Git 정책: Drive 전용 문서이며 Git에 중복 반영하지 않음

## 1. 적용된 최신 업무환경

| 구분 | 관리 위치 | 관리 대상 |
|---|---|---|
| Git | `C:\sk-encoa\codex_game` | Unity 소스, 런타임 에셋, 자동 테스트, 빌드·배포 설정 |
| Drive | `codex_game_documents/programer` | 기술 검토, 예상 시간, 의사결정, 테스트 결과, Codex 활용 기록 |

- Drive 동기화 폴더 안에서 활성 Git 작업트리를 운영하지 않는다.
- Git 저장소에 Drive 또는 Obsidian 동기화 사본을 연결하지 않는다.
- 동일 문서를 Git과 Drive 양쪽에서 중복 편집하지 않는다.
- `dev`는 일반 개발과 검증 기준으로 사용한다.
- `pub`는 총괄과 사용자의 승인 후 통합 빌드와 공개 배포에 사용한다.
- 코드 결과는 브랜치, PR 또는 커밋 SHA와 실행·테스트 결과를 Drive 문서에 연결한다.
- Drive 규칙을 확인하지 못해 기술 판단의 기준이 불명확하면 해당 결정을 보류한다.

## 2. 기존 예상시간에 미치는 영향

기존 [Unity_예상_작업시간.md](Unity_예상_작업시간.md)의 개발 시간 범위는 유지한다.

| 항목 | 예상 영향 |
|---|---:|
| Git-Drive 최초 분리 환경 확인 | 기존 프로젝트 설정 4~6시간에 포함 |
| Drive 문서와 Git SHA 연결 기록 | 주요 단계당 0.5~1시간 |
| 다른 기기 환경 재현 검증 | 2~4시간 |
| 단순 규칙·경로·보고 형식 변경 | 변경 1회당 1~4시간 |
| 빌드 대상·플랫폼·검증 조건 변경 | 변경 1회당 1~5일 |
| 기준 문서 미동기화로 결정 보류 | 개발시간이 아닌 달력 일정 증가 |

주요 단계별 보고와 다른 기기 검증을 모두 포함하면 전체 일정에 약 4~8시간의 운영 여유를 추가한다.

- 순수 구현·검증: 136~184시간
- 분리 업무환경 운영 여유 포함: 140~192시간
- 1일 8시간 기준: 약 18~24 작업일
- 현실적 달력 일정: 약 3~4주 이상

## 3. 향후 추가 공유 규칙 반영 원칙

1. 작업 시작 직전에 Drive의 공통 규칙과 프로그래머 규칙을 다시 확인한다.
2. 새 규칙의 적용일, 대상 역할, 기존 규칙 대체 여부와 필수 조건을 확인한다.
3. 새 규칙이 작업공간, 빌드 대상, 검증 환경 또는 제출 조건을 바꾸면 예상 시간을 다시 산정한다.
4. 다른 역할 문서는 직접 수정하지 않고 필요한 판단을 해당 역할 또는 총괄에 요청한다.
5. Git 코드와 Drive 문서는 브랜치·커밋 SHA·문서 링크로 연결하되 동일 내용을 중복 편집하지 않는다.
6. 규칙 충돌이나 기준 원본이 불명확하면 임의 적용하지 않고 결정 요청으로 보고한다.
7. 작업 도중 새 규칙이 공유되면 목표와 직접 충돌하는지 먼저 확인하고 충돌하지 않는 작업만 계속한다.

## 4. 프로그래머 공유 보고 형식

1. 요청: 요청자, 날짜, 목적, 완료 조건과 우선순위
2. 대상: Git 저장소·브랜치·파일 또는 Drive 폴더·문서
3. 진행: 실행 작업, 선택 방법, 변경 범위와 보존한 기존 작업
4. 검증: 환경, 명령·체크리스트, 대상 커밋 SHA와 증거
5. 결과: 완료·부분 완료·차단 상태, 산출물과 남은 위험
6. 결정 요청: 총괄 또는 다른 역할이 판단할 사항과 필요한 기한
