## #54 쓰리 콜 카드 겹침 최종 계약

1. `HalliPileOverlapLayout.MaximumPileCards`는 `2`로 고정한다.
2. `HalliDevPanel`은 최신 카드와 직전 카드만 유지하고 그 이전 카드는 화면 기록에서 제거한다.
3. 64px 카드에서 `CardStepX=59`를 유지해 가로 겹침을 5px, 약 7.8%로 제한한다.
4. 공개 이력을 오래된 카드부터 그려 최신 카드가 마지막에 그려지고 최상단에 보이게 한다.
5. 카드 ID, 공개 주체, 상대 기준 좌우 변환, 벨 판정 로직은 변경하지 않는다.
6. #46의 최대 3장·먼저 나온 카드 최상단 계약과 시안은 `ArtReferences/Archive/LegacyContract/`에서만 보관하며 구현 근거로 사용하지 않는다.

## 충돌 방지 규칙

1. 재오픈 버그의 명시적 기대 결과가 기존 아트 시안과 충돌하면 재오픈 버그를 우선한다.
2. 현재 카드 겹침의 단일 기준은 `ArtReferences/Halli_0_4_2/`와 #54다.
3. `audit_runtime_art_bindings_0_6_2.ps1`은 최대 표시 수, 겹침 비율, 최신 카드 최상단 조건이 달라지면 실패한다.
4. 구형 인계서와 시안은 `Archive`로 이동하고 현재 경로에 중복 기준을 두지 않는다.

## 장면 재생성 게이트

현재 `Assets/Scenes/PlayableDev.unity`에는 `MainMenu_0_5_6` 6개, `GuideNav_0_5_6` 14개, `StageReward_0_5_4` 3개 GUID가 남아 있다. WebGL 빌드 함수는 `CreateScene()`을 호출하지만, Unity에서 기존 장면을 바로 열어 Play하면 저장된 구형 참조가 보일 수 있다.

모든 연결 수정 후 반드시 다음 순서로 검증한다.

1. `Codex Game/Playable Dev/Create Scene` 실행

3. 구형·보관 경로 GUID 참조 0건 확인
4. ko/en 및 960×540 실행 스크린샷 첨부
5. 그 뒤에만 WebGL 후보 생성
