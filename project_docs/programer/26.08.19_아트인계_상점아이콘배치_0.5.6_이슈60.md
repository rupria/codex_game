# 이슈 #60 상점 아이콘·재화 UI 아트 인계 — ShopItemIcons 0.5.6

## 확인된 원인

신규 아이템 원화는 이미 `IconOverhaul_0_5_1`과 `ItemExpansion_0_5_2`에 80px 팝업용으로 존재한다. 그러나 `PlayableDevSceneBuilder`의 상점 바인딩은 구형 64px 기본 아이콘을 다시 불러오고, `BarShopDevPanel.DrawSlot()`은 이를 56×56으로 축소한다. 또한 230×210 슬롯 텍스처를 실제 190×174 영역에 강제 스트레치하여 프레임과 내부 배치가 눌린다.

## 추가된 위치

- 런타임 PNG: `Assets/Art/Prototype/UI/ShopItemIcons_0_5_6/`
- 편집 원본·Aseprite 생성 스크립트: `ArtReferences/ShopItemIcons_0_5_6/source/`
- 960×540 상점 시안: `ArtReferences/ShopItemIcons_0_5_6/preview/issue_60_shop_item_layout_preview_960x540_0_5_6.png`
- 자산 접촉 시트: `ArtReferences/ShopItemIcons_0_5_6/preview/shop_item_icon_assets_contact_sheet_620x240_0_5_6.png`
- 좌표·기존 원화 재사용표: `ArtReferences/ShopItemIcons_0_5_6/shop_item_icons_art_catalog_0_5_6.json`
- 승인 해시: `ArtReferences/ShopItemIcons_0_5_6/APPROVED.sha256`

## 추가·교체 자산

- 실제 런타임 크기 전용 슬롯 `bar_shop_product_slot_190x174_0_5_6.png`
- 아이콘 플레이트 idle / hover / disabled 88×88
- 기본 탄환·임시 탄환 재화 아이콘 48×48
- 가격용 기본 탄환 28×28

## 프로그래머 연결 작업

1. `BarShopUiArtSet._slotFrame`을 230×210 구형 프레임에서 `bar_shop_product_slot_190x174_0_5_6.png`로 교체한다.
2. `DrawSlot()`의 아이콘을 로컬 `(55,14,80,80)`에 배치하고, 상태 플레이트는 `(51,10,88,88)`에 먼저 그린다.
3. 상점 제품 바인딩 8종을 구형 64px 기본 자산이 아닌 카탈로그의 `reuseBindings` 80px 팝업 자산으로 교체한다.
4. 제품명은 로컬 `(12,112,166,20)`, 가격은 `(60,134,70,28)`, 구매 버튼은 `(24,140,142,28)`을 기준으로 배치한다. 가격·버튼의 실제 겹침이 없도록 텍스트 baseline을 확인한다.
5. `EconomyUiArtSet`의 기본·임시·가격 아이콘을 각각 48px / 48px / 28px 0.5.6 자산으로 교체한다.
6. 임시 탄환은 회색 탄피와 황동 모래시계 균열 표식, 기본 탄환은 넓은 황동 실루엣으로 유지해 작은 화면에서도 구분한다.
7. 아이템 가격, 구매 규칙, 임시 탄환 선차감, 인벤토리와 상점 데이터는 변경하지 않는다.

## 검수 조건

- 스테이지 시작, 아이템 인벤토리, 상점의 기본·임시 탄환이 같은 모양으로 표시된다.
- 8종 아이템 모두 상점 슬롯에서 80×80 크기와 동일한 중심·시각 면적을 사용한다.
- 제품명, 가격, 구매 버튼이 서로 겹치거나 프레임 밖으로 나오지 않는다.
- hover / disabled 상태에서 아이콘 플레이트가 바뀌되 아이콘 자체 위치는 흔들리지 않는다.
- 960×540, 1280×720, 1920×1080과 ko/en 긴 이름을 확인한다.
- 상점 구매 애니메이션과 총알 주머니 영역은 이번 변경으로 이동하지 않는다.
