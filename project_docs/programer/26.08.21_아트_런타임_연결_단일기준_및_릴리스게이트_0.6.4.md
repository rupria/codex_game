# 아트 런타임 연결 단일 기준 및 릴리스 게이트 0.6.4

> 기준 브랜치: `dev`
> 기준 매니페스트: `current_art_runtime_manifest_0_6_4.json`
> 필수 게이트: `audit_runtime_art_bindings_0_6_4.ps1`
> 계기: 빌드 `0.1.2.07.02`의 최신 아트 미노출 회귀

## 1. 이 문서가 해결하는 문제

`0.1.2.07.02`에는 최신 아트 파일이 존재했지만 런타임 빌더와 저장 장면이 구형 패키지를 계속 참조했다. 기존 `0.6.3` 감사 도구도 `builderBound=False`와 구형 장면 참조를 출력하면서 성공으로 종료해 빌드를 차단하지 못했다.

따라서 앞으로는 파일 존재, 이슈 코멘트 또는 기능 테스트 통과를 아트 적용 완료로 간주하지 않는다. **승인 아트, 런타임 연결, 저장 장면, 실제 화면과 정확한 빌드 SHA가 모두 일치할 때만 완료**다.

## 2. 상태 명칭 재설정

아트 관련 상태는 아래 여섯 단계로만 기록한다.

1. `ART_PRODUCED`: 최종 PNG·원본·카탈로그가 생성됨
2. `ART_APPROVED`: 사용자가 시안을 승인함
3. `RUNTIME_BOUND`: 최신 패키지가 빌더·ArtSet·표시 클래스에 연결됨
4. `SCENE_SAVED`: 최신 연결로 장면을 재생성하고 저장함
5. `BUILD_VERIFIED`: 동일한 전체 SHA의 실제 빌드에서 화면을 확인함
6. `DONE`: 1~5를 모두 만족하고 증거가 남음

`ART_PRODUCED`나 `ART_APPROVED` 상태에서 이슈를 닫거나 “적용 완료”라고 기록하지 않는다. 이슈의 닫힘 상태도 `RUNTIME_BOUND`나 `BUILD_VERIFIED`의 증거가 아니다.

## 3. 단일 최신 기준

- 현재 실행 기준은 정확히 `current_art_runtime_manifest_0_6_4.json` 한 파일이다.
- 파일 수정 시간, 폴더명의 숫자 비교, 마지막 이슈 코멘트 순서로 최신본을 추정하지 않는다.
- 새 승인본이 생기면 매니페스트 리비전을 올리고 `supersedes`와 `replaces`를 명시한다.
- 이전 파일은 이력 보관만 하며 빌더·ArtSet·장면에서 참조하지 않는다.
- 구형 이미지를 새 이미지와 함께 활성 경로에 병렬 연결하지 않는다.
- 재오픈된 명시적 수용 기준은 이전 시안보다 우선하되 매니페스트 리비전을 반드시 올린다.
- 현재 할리갈리 카드 더미 고정 계약은 `최대 2장`, `가로 겹침 10% 이하`, `최신 공개 카드 최상단`이다. #46의 3장 기준을 복구하지 않는다.

## 4. 작업 순서

1. `origin/dev` 전체 SHA와 깨끗한 통합 작업공간을 확인한다.
2. 승인 아트와 매니페스트 리비전을 고정한다.
3. 프로그래머가 빌더·ArtSet·표시 클래스에 최신 패키지를 연결한다.
4. `Codex Game/Playable Dev/Create Scene`으로 장면을 재생성하고 저장한다.
5. `audit_runtime_art_bindings_0_6_4.ps1`을 실행한다.
6. 자동 테스트와 Unity 컴파일을 실행한다.
7. 메인·가이드·할리갈리·포커·상점의 960×540 실제 화면을 승인본과 대조한다.
8. 위 검증을 수행한 동일한 전체 SHA에서만 빌드를 만든다.

## 5. 빌드 차단 조건

아래 항목 중 하나라도 발생하면 게이트는 종료 코드 1과 `ART_RUNTIME_RELEASE_GATE_FAILED`를 반환해야 한다.

- 필수 최신 아트 폴더가 없음
- 최신 패키지가 `PlayableDevSceneBuilder`에 없음
- 최신 패키지 GUID가 저장 장면에 없음
- 구형 패키지가 빌더나 저장 장면에 남아 있음
- Archive 패키지가 `Assets` 실행 경로로 복구됨
- 할리갈리 카드 더미의 2장·10%·최신 카드 최상단 계약이 깨짐
- #67·#68·#73·#74 포커 UI 수용 조건이 충족되지 않음

`ART_RUNTIME_RELEASE_GATE_OK`가 없으면 WebGL, 로컬 플레이 패키지와 배포 링크를 만들지 않는다.
