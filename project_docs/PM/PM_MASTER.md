## 버전 및 pub 승인

- PM이 변경 영향에 따라 Major / Minor / Patch 증가 수준을 결정한다.
- 공식 배포한 버전은 수정하지 않고 모든 변경을 새 버전으로 발행한다.
- `dev` QA 통과는 `pub` 반영의 자동 승인이 아니다.
- 사용자 명시적 승인 없이 `pub` 병합·태그·외부 배포를 진행하지 않는다.

## GitHub 프로젝트 운영

- 흐름: `Backlog → Ready → In Progress → In Review → Validation → Done`
- 필수 필드: Status, Workstream, Priority, Target, Owner, QA Result.
- 개발 작업은 산출물 또는 커밋이 있어야 Validation으로 이동한다.
- QA PASS 또는 승인된 CONDITIONAL만 Done으로 이동한다.
- 문서의 Git 공유는 사용자가 별도로 요청한 경우에만 진행한다.

## 선택 가산점

필수 웹 빌드와 공개 링크가 완료된 후에만 진행 여부를 결정한다.

- 3분 이내 데모 영상: 게임 소개 → 실제 플레이 → 핵심 기능
- Codex 활용 설명: 사용 영역 → 구현 기능 → 해결 문제 → 사람의 결정
- 선택 자료가 필수 빌드의 안정성과 검증 시간을 줄이면 중단한다.
