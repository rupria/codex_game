# 가이드 및 카드 UI 개선 기준

## 1. 작업 범위

- 이 문서는 가이드의 내용·동작과 카드 UI가 전달해야 할 정보·수용 기준을 정의한다.
- 이슈 #19의 카드 UI 시각 개선용 아트는 별도 작업 중이며, 이 문서에서 아트 에셋이나 픽셀 좌표를 다시 요청하지 않는다.
- 프로그래머는 전달받은 아트를 연결하면서 아래 정보 우선순위, 입력 차단과 다국어 문구를 구현한다.
- 최신 게임 규칙은 [[게임진행플로우_0.1.2.2]]을 우선하고 인게임 표시 문자열은 [[07_인게임_텍스트_최소화_및_재화_UI_기준]]을 따른다.

## 2. 현재 화면의 문제

### 가이드

- 반투명 가이드 뒤로 메인 타이틀, 시작·가이드 버튼과 언어 버튼이 함께 보여 문장이 겹친다.
- 가이드가 열린 상태에서도 뒤쪽 UI가 버튼처럼 보여 클릭 가능 여부를 오해하게 한다.
- 현재 가이드는 `W`, `Q/E`, `1/2` 조작만 안내해 전체 목표, 정답 조합, 카드 획득, 포커 카드 구성과 패배 결과를 설명하지 못한다.

### 카드 UI

- 커뮤니티 카드, 카드 더미, 남은 덱, 배분 횟수, 타이머와 상태 문구가 화면 중앙에서 서로 경쟁한다.
- 어느 카드 영역이 왼쪽·오른쪽 벨 판정에 연결되는지 한눈에 구분하기 어렵다.
- 하단 획득 카드 패널이 크게 보이지만 카드 장수와 실제 획득 카드의 관계가 즉시 읽히지 않는다.
- 카드와 안내 문구가 겹칠 수 있어 랭크·문양·해골 수 확인을 방해한다.

## 3. 가이드 표시 방식

- 가이드는 별도 화면 전환 또는 화면 전체를 덮는 불투명 모달 중 하나로 구현한다.
- 모달 방식이면 뒤쪽 메인 UI의 글자와 버튼 형태를 식별할 수 없을 정도로 가려야 한다.
- 가이드가 열려 있는 동안 뒤쪽 버튼, 언어 변경, 게임 시작과 게임 플레이 입력을 처리하지 않는다.
- 메인 화면에서 가이드를 열면 게임 타이머는 시작하지 않는다.
- 가이드는 4쪽으로 구성하며 아트에 포함된 아이콘형 `이전`, `다음`, `닫기` 조작과 `ESC` 닫기를 제공한다.
- 아이콘 위에 회색 텍스트형 버튼을 중복 표시하지 않고, 별도의 하단 페이지 번호 박스를 추가하지 않는다. 현재 페이지는 각 페이지의 제목·내용·페이지 아트로 구분한다.
- 첫 쪽에서는 이전 아이콘이 경계를 넘지 않고 마지막 쪽에서는 다음 아이콘이 경계를 넘지 않는다.
- 페이지를 바꿔도 언어 설정은 유지하며 한국어와 영어 모두 같은 정보 구조를 사용한다.

## 4. 최종 가이드 문구

### 1 / 4 — 목표와 게임 흐름

```text
1. 첫 커뮤니티 카드 공개
2. 할리갈리에서 카드를 획득
3. 개인 카드 3장 + 커뮤니티 카드 2장으로 포커
4. 포커 패자는 HP 1 감소

AI HP를 0으로 만들면 승리합니다.
```

### 2 / 4 — 할리갈리 판정

```text
W 또는 카드 더미 클릭: 카드 1장 펼치기
Q/E 또는 벨 클릭: 왼쪽/오른쪽 판정

같은 문양의 해골 합이 정확히 3이면 정답입니다.
가능한 조합: 1+2 또는 해골 3 한 장

승패 후 2초 잠금이 끝나면 30초 안에 판단하세요.
오답·시간 초과는 상대 승리 1회입니다.
목표 승수를 먼저 채우거나 최대 12회·덱 소진 시 종료합니다.
```

### 3 / 4 — 카드 획득과 포커

```text
1+2 정답: 두 카드 모두 획득
해골 3 정답: 해당 해골 3 카드 한 장 획득

획득 카드는 현재 전투의 포커까지 유지됩니다.
할리갈리 종료 후 포커에 사용할 개인 카드 3장을 확정합니다.
부족한 카드는 미획득 카드에서 무작위로 보충됩니다.

포커는 개인 3장과 커뮤니티 2장,
정확히 5장을 모두 사용합니다.
```

### 4 / 4 — 예측과 승리

```text
1: 플레이어 승리 예측 / 2: AI 승리 예측
제한 시간은 2분이며 예측은 실제 승패를 바꾸지 않습니다.

같은 족보는 랭크 비교 후 문양 순서로 결정합니다.
♠ 스페이드 > ♦ 다이아몬드 > ♥ 하트 > ♣ 클로버

포커 패자는 HP 1 감소합니다.
AI HP가 0이 되면 잔여 플레이어 HP 1당 총알 1개를 받습니다.
```

## 5. 카드 UI 기능 기준

아트의 최종 구도와 장식은 아트 작업 결과를 따르되 다음 기능 기준은 유지한다.

### 판정 카드와 벨

- 왼쪽·오른쪽 판정 영역을 위치, 외곽선, 색 또는 연결 표시 중 둘 이상으로 구분한다.
- 각 판정 영역이 중앙의 어느 벨과 연결되는지 설명 없이 식별할 수 있어야 한다.
- 앞면 카드의 랭크, 문양과 해골 수가 `960×540`에서 서로 겹치지 않고 읽혀야 한다.
- 뒤집기 연출이 완료되지 않은 카드는 판정 대상처럼 보이지 않게 한다.
- 카드가 공개되는 동안에도 활성 벨은 클릭 가능하며, 2초 잠금 중에는 비활성 상태가 명확해야 한다.

### 커뮤니티 카드와 카드 더미

- 첫 커뮤니티 카드와 잠긴 두 번째 커뮤니티 카드의 역할을 구분한다.
- `배분 {current}/12`, `남은 덱 {remaining}`은 카드 앞면을 가리지 않는 위치에 표시한다.
- 30초 판정 타이머는 두 벨과 가까운 한곳에만 표시하고 카드 더미·조작 문구와 겹치지 않게 한다.
- `W 1장 펼치기`와 마우스로 누르는 카드 더미는 같은 입력임을 시각적으로 연결한다.

### 대면형 덱 배치와 카드 제출 연출

- 흰색으로 표시된 영역은 배치 검토용 여백이며, 실제 게임에서는 기존 살룬·원형 테이블 배경이 끊기지 않고 이어져야 한다. 흰색 패널이나 빈 UI 박스를 새로 추가하지 않는다.
- 플레이어와 AI가 테이블을 사이에 두고 마주 앉았다는 인상을 주기 위해 카드 펼치기 저장소를 세로 중심축의 위·아래에 분리한다.
  - AI 카드 덱: 화면 상단 중앙, 상대 자리 앞
  - 플레이어 카드 덱: 화면 하단 중앙, 플레이어 자리 앞
- 왼쪽·오른쪽 판정 카드 더미와 중앙 벨 2개는 기존 판정 구조를 유지한다. 이번 변경은 판정 규칙을 바꾸는 것이 아니라 **각 카드가 누구의 덱에서 나왔는지 이동 경로로 보여주는 연출 변경**이다.
- 카드가 판정 위치에서 갑자기 생성되거나 같은 중앙 덱에서 양측 카드가 모두 나오는 표현은 사용하지 않는다.
- 카드 공개 순서와 출발점은 다음과 같이 고정한다.

```text
1. 플레이어 왼쪽 카드: 하단 플레이어 덱 → 해당 왼쪽 판정 슬롯으로 위쪽 이동
2. AI 왼쪽 카드: 상단 AI 덱 → 해당 AI 왼쪽 판정 슬롯으로 아래쪽 이동
3. 플레이어 오른쪽 카드: 하단 플레이어 덱 → 해당 오른쪽 판정 슬롯으로 위쪽 이동
4. AI 오른쪽 카드: 상단 AI 덱 → 해당 AI 오른쪽 판정 슬롯으로 아래쪽 이동
```

- AI의 왼쪽·오른쪽은 D-006의 `AI 본인 기준` 슬롯 매핑을 그대로 사용한다. 화면 좌표를 새로 해석해 카드 판정 위치가 뒤바뀌지 않도록 논리 슬롯과 화면 슬롯의 대응표를 구현 데이터에서 명시한다.
- 각 공개는 덱 맨 위의 카드 뒷면 한 장이 분리되어 목표 슬롯까지 이동한 뒤 앞면으로 전환되는 흐름을 사용한다.
- 카드 앞면 전환은 이동이 끝나기 직전 또는 도착 시점에 시작한다. 판정 가능 시점은 기존 D-005의 `앞면 전환 완료`를 유지한다.
- AI 덱과 이동 중 뒷면 카드는 상대 방향을 나타내도록 180도 회전할 수 있다. 앞면 공개가 끝난 카드는 랭크·문양·해골 판독을 위해 플레이어 기준 정방향으로 표시한다.
- 플레이어 카드의 이동 방향은 `아래 → 위`, AI 카드의 이동 방향은 `위 → 아래`로 일관되게 유지한다. 좌우 이동만으로 카드를 내는 연출은 사용하지 않는다.
- 새 카드가 기존 카드 위에 포개지더라도 이전 카드의 랭크·문양·해골 수가 남아 있어야 한다. 도착점은 벨·타이머·상태 문구의 클릭·판독 영역과 겹치지 않는다.
- 카드 이동 중에는 출발 덱의 장수가 실제로 1장 감소하고, 카드가 출발 덱과 도착 슬롯에 동시에 존재하는 것처럼 보이지 않아야 한다.
- 플레이어 카드에는 청록색, AI 카드에는 붉은색의 짧은 출발 강조 또는 테두리를 사용할 수 있다. 효과는 카드 앞면 판독보다 강하지 않게 하고, 색만으로 소유자를 구분하지 않는다.

연출이 전달해야 할 문장:

> 아래의 내가 카드를 내고, 맞은편 위쪽의 AI가 응수해 카드를 내며, 두 카드가 테이블 중앙의 같은 승부 영역에 쌓인다.

### 획득 카드

- 플레이어 획득 카드는 앞면과 총 장수를 함께 표시한다.
- AI 획득 카드는 뒷면과 총 장수를 표시해 숨겨진 정보는 공개하지 않는다.
- 획득 카드가 늘어나도 패널 밖으로 넘치거나 다른 조작 영역을 덮지 않도록 겹침, 스크롤 또는 페이지 처리를 제공한다.
- 획득 카드 UI는 해당 카드가 다음 5장 승부까지 유지됨을 카드 이동·고정 위치·아이콘으로 전달하고 `포커` 명칭을 표시하지 않는다.

### 상태와 입력 피드백

- 정답, 오답, 시간 초과, 2초 잠금과 입력 가능 상태를 동일 위치의 짧은 상태 문구로 표시한다.
- 상태 문구는 커뮤니티 카드, 판정 카드와 벨을 가리지 않는다.
- 마우스 클릭 영역은 보이는 카드·벨·더미의 경계와 일치하고 서로 겹치지 않는다.
- 비활성 외형과 실제 입력 가능 상태가 항상 일치해야 한다.

### 메인 START·GUIDE 버튼

- `START`와 `GUIDE`는 동일한 너비·높이·프레임·내부 배경·패딩 규칙을 사용한다.
- 보이는 버튼 전체가 클릭 영역이며 외곽 프레임과 실제 입력 영역이 어긋나지 않아야 한다.
- 버튼 내부에 기본 IMGUI 버튼이나 잔여 텍스트를 한 겹 더 표시하지 않는다.
- 한국어와 영어에서 라벨을 버튼 중앙에 유지하고, 하단 언어·조작 안내와 겹치지 않는 여백을 확보한다.
- hover·pressed·disabled 상태는 같은 버튼 경계 안에서 바뀌고 클릭 1회가 동작 1회만 발생시킨다.

### HP 하트 표시

- 플레이어와 AI의 현재 HP를 화면 상단 각자의 영역에 하트 3칸으로 표시한다.
- 현재 기준 최대 HP는 `3`이며 채워진 하트는 현재 HP, 빈 하트 또는 어두운 하트는 잃은 HP를 나타낸다.
- 참가자 라벨과 위치를 함께 유지해 색상만으로 플레이어와 AI를 구분하지 않는다.
- 포커 피해가 확정되는 순간 하트를 갱신하고 승자 쪽 하트는 변경하지 않는다.
- 텍스트 `HP {current}/{max}`를 보조 정보로 남길 수 있으나 하트와 값이 항상 같아야 한다.
- 이후 최대 HP 규칙이 변경되면 UI에 3을 별도 하드코딩하지 않고 게임 규칙 데이터의 최대 HP를 사용한다.

### 30초 밧줄 타이머

- 30초 벨 입력 제한을 카드 펼치기 영역 하단의 밧줄과 큰 숫자 초로 함께 표시한다.
- 숫자와 밧줄 길이는 동일한 남은 시간 값을 사용하며 `남은 시간 / 30초` 비율로 밧줄 진행을 계산한다.
- 30~11초는 일반 상태, 10~1초는 불꽃 크기·흔들림·밧줄 형태 변화가 포함된 긴급 상태로 구분한다.
- 0초에는 폭발 연출을 한 번만 재생하고 기존 시간 초과 패배 판정도 한 번만 발생한다.
- GUIDE, 최초·스테이지 전환, 결과 직후 2초 잠금, 타이머 비활성·일시정지 상태에서는 밧줄과 숫자 모두 진행하지 않는다.
- 결과 직후 2초 잠금의 남은 시간을 30초 밧줄 타이머 값으로 표시하지 않는다.
- 새 할리갈리 라운드에서 밧줄 길이·불꽃·폭발 상태를 초기화한다.
- 0초와 벨 입력이 경합해도 기존 판정 우선순위를 유지하며 승패·승수·폭발을 중복 처리하지 않는다.
