# UI 다국어 현지화 기준

> 최신 표시 기준은 [[07_인게임_텍스트_최소화_및_재화_UI_기준]]과 [[게임진행플로우_0.1.2.2]]을 우선한다. `총알`, `일회성 총알`, `할리갈리`, `포커`는 내부 문자열·접근성·로그에서만 유지하고 일반 플레이 화면에는 렌더링하지 않는다.

## 1. 목적

게임 화면에 직접 작성된 영어 문장을 고유 Key 기반의 외부 문자열 데이터로 분리한다. 사용자는 번역 원본의 `ko`, `en` 열을 직접 수정하고, 게임은 현재 선택 언어에 맞는 열을 런타임에 조회해 표시한다.

번역 원본:

- [CODEX GAME · UI 다국어 문자열 원본 0.1](https://docs.google.com/spreadsheets/d/1FNdvJsfkN_rhKSwQWhlZfSnzKiqFtlFvmeYakUQp58Q/edit)
- 현재 등록 Key: 137개
- 기본 언어: `ko`
- 대체 언어: `en`

## 3. 확정 데이터 구조

번역 원본은 하나의 넓은 형식 CSV와 동일한 구조를 사용한다.

| 열 | 용도 | 수정 주체 |
|---|---|---|
| ID | 사람이 행을 찾기 위한 순번. 코드 참조 금지 | 자동 또는 기획 |
| Key | 코드가 참조하는 영구 고유 키 | 기획·프로그래머 합의 |
| ko | 한국어 표시 문자열 | 사용자 편집 가능 |
| en | 영어 표시 문자열 | 사용자 편집 가능 |
| 화면/상태 | 사용 위치 | 기획 |
| 변수 | `{stage}`, `{count}` 형태의 치환 변수 | 기획·프로그래머 |
| 현재 소스 | 기존 하드코딩 위치 | 조사 기록 |
| 비고 | 줄바꿈·브랜드·검토 필요 사항 | 기획 |
| 키 검증 | 중복 Key 확인 | 자동 |

코드에서는 `ID 1` 같은 숫자 대신 `UI_MAIN_START` 같은 의미형 Key를 사용한다. 행 삽입이나 정렬로 ID가 바뀌어도 게임 연결이 깨지지 않아야 한다.

### Key 규칙

```text
UI_[화면 또는 기능]_[의미]
STATUS_[단계]_[상태 또는 결과]
```

- 영문 대문자와 밑줄만 사용한다.
- 공개된 Key의 의미를 바꾸지 않는다.
- 사용하지 않는 Key도 즉시 재사용하지 않고 폐기 상태로 보존한다.
- 같은 문장이라도 문맥이나 변수 구성이 다르면 별도 Key를 사용한다.

### 변수 규칙

```text
ko: 스테이지 {stage}
en: STAGE {stage}
```

- 모든 언어에서 변수 이름과 개수가 같아야 한다.
- 변수 값은 번역 데이터에 직접 넣지 않는다.
- 복수형·어순이 달라지는 복합 문장은 언어별 전체 문장 안에서 변수 위치를 조정한다.

## 4. 권장 런타임 방식

### 4.1 원본과 배포 데이터

```text
Google 스프레드시트 번역 원본
→ UTF-8 CSV 내보내기 및 자동 검증
→ Assets/StreamingAssets/Localization/ui_strings.csv
→ Unity 시작 시 비동기 로드
→ 현재 언어 열 조회
```

- Google 스프레드시트를 번역 기준 원본으로 사용한다.
- 저장소의 CSV는 게임 실행용 산출물이며 독립적으로 수정하지 않는다.
- WebGL에서는 `StreamingAssets`를 `UnityWebRequest`로 비동기 로드한다.
- CSV를 원격 Google Sheet에서 게임이 직접 읽게 하지 않는다. 네트워크·권한·버전 불일치가 게임 시작을 막지 않아야 한다.
- 배포본 번역 변경은 CSV 갱신 후 새 빌드를 배포한다.
- Unity Editor에서는 개발 편의를 위해 CSV 다시 읽기 기능을 제공할 수 있다.

### 4.2 조회 인터페이스

권장 책임 구조:

```text
LocalizationCatalog
  - CSV 파싱과 Key/언어 값 보관

LanguageSettings
  - 현재 언어 코드 보관
  - 기본값 ko
  - 변경 이벤트 발행

ILocalizer
  - Get(Key, variables)
  - 현재 언어 → en → [MISSING:KEY] 대체
```

현재 UI는 IMGUI이므로 `OnGUI`에서 매 프레임 Key를 조회하면 언어 변경 직후 다시 그려진다. 완성 문장을 필드에 장기간 캐시하지 않는다.

### 4.3 Application 상태 문장

다음과 같이 완성 영어 문장을 Snapshot에 전달하는 구조를 폐기한다.

```text
StatusMessage = "Distributing card 2/4: PLAYER LEFT."
```

대신 표시 의미와 변수만 전달한다.

```text
StatusKey = STATUS_HALLI_DISTRIBUTING
StatusArgs = { step: 2, actor: UI_ACTOR_PLAYER, side: UI_SIDE_LEFT }
```

Core와 Application 계층은 표시 언어를 알지 않는다. Presentation 계층이 최종 문자열을 만든다.

## 5. 언어 선택 UI

- 최초 실행 기본 언어는 한국어(`ko`)다.
- 메인 화면에서 `한국어 / English`를 선택할 수 있어야 한다.
- 언어 변경 시 메인, 가이드, 할리갈리, 개인 카드 선택, 포커, 결과 화면의 모든 문자열이 재시작 없이 갱신된다.
- 선택 언어는 로컬 설정에 저장하고 다음 실행 시 복원한다.
- 키보드 표기 `W`, `Q/E`, `1/2`, `ENTER`, `ESC`는 번역하지 않는다.
- `CODEX GAME` 브랜드명은 번역하지 않는다.

## 6. 누락과 오류 처리

조회 순서:

```text
선택 언어 값
→ en 값
→ [MISSING:KEY]
```

- 없는 Key와 빈 번역은 콘솔에 Key별 1회만 경고한다.
- 중복 Key, 빈 `ko`, 빈 `en`, 언어별 변수 불일치는 CSV 내보내기나 빌드 전에 실패 처리한다.
- 사용자 화면에 예외 스택이나 빈 문자열을 표시하지 않는다.

## 7. 폰트 기준

- WebGL에서도 한글이 깨지지 않는 폰트를 명시적으로 지정한다.
- 한글·라틴 문자·숫자·키보드 기호·카드 문양 기호가 모두 포함되어야 한다.
- 폰트 라이선스와 출처를 Obsidian의 라이선스 기록에 남긴다.
- 글자 폭이 달라지므로 한국어와 영어 양쪽에서 버튼 잘림·줄바꿈·겹침을 검증한다.

## 8. 현재 기획과 구현 충돌 확인 항목

문자열 조사 과정에서 다음 기존 구현 문구가 최신 기획과 다를 가능성을 확인했다. 번역만 적용하지 말고 상태 로직과 함께 최신 명세를 따른다.

1. `Player exceeded the 30-second flip limit.`
   - 최신 기준은 승패 직후 2초 잠금 1회 후 시작되는 30초 벨 입력 제한이다.
2. 오조작 뒤 보상 카드 선택 관련 문구
   - 최신 확정 기준은 상대의 승리 1회만 기록한다.
   - 패배 참가자의 이전 정상 획득 카드는 현재 전투의 포커 라운드까지 유지하며, 빼앗거나 별도의 보상 카드 선택 단계로 이동하지 않는다.
3. `Coin bonus values and item effects are pending design.`
   - 공개 빌드에서 제거한다.
   - 공개 화면에는 재화 명칭을 사용하지 않고 기본·일회성 재화 아이콘과 숫자를 분리 표시한다.
   - AI HP가 0이 되면 밸런싱 데이터에 따라 기본·일회성 재화를 별도 정산한다.
   - 바 상점의 아이템·체력 회복은 값이 확정된 항목만 표시하며 `미확정` 안내 문구를 노출하지 않는다.

번역 표에는 현행 UI를 누락 없이 추적하기 위해 위 문자열도 포함했으며 `비고` 열에 검토 필요 표시를 남겼다.

## 9. 프로그래머 전달 수용 기준

- [ ] 메인 화면 기본 표기가 `시작`, `가이드`로 보인다.
- [ ] 가이드는 별도 화면 또는 뒤쪽 UI가 보이지 않는 불투명 모달로 표시되고 뒤쪽 입력을 차단한다.
- [ ] 가이드는 장르 명칭 없이 카드·벨 판정, 카드 획득, 5장 비교와 예측 규칙을 아이콘·예시 중심으로 전달한다.
- [ ] 메인 화면에서 한국어와 영어를 선택할 수 있다.
- [ ] 언어 변경 즉시 현재 화면과 이후 모든 화면이 같은 언어로 갱신된다.
- [ ] Presentation 계층의 사용자 노출 문자열이 모두 Key 조회로 전환된다.
- [ ] Application/Core 계층은 완성된 사용자 노출 문장을 보관하지 않고 Key와 변수만 전달한다.
- [ ] Google Sheet에서 내보낸 UTF-8 CSV를 게임이 로드한다.
- [ ] Key 중복·빈 한국어·빈 영어·변수 불일치가 빌드 전에 탐지된다.
- [ ] 누락 Key는 `en`, 이후 `[MISSING:KEY]`로 대체된다.
- [ ] WebGL에서 한글, 카드 문양, 줄바꿈이 깨지지 않는다.
- [ ] 960×540 기준으로 한국어와 영어 UI에 잘림·겹침이 없다.
- [ ] 오답·시간 초과 시 기존 획득 카드가 유지되고 별도의 상대 보상 카드 선택 화면이 나타나지 않는다.
- [ ] HUD·스테이지 종료·바 상점은 재화 명칭 없이 기본·일회성 재화 아이콘과 숫자만 표시한다.
- [ ] AI HP가 0이 되면 기본 재화와 일회성 재화 지급량을 서로 다른 아이콘과 숫자로 분리 표시한다.
- [ ] 최초 시작과 다음 스테이지 전환에 가게 이동, 살룬 입장, 상대 소개와 중앙 원형 테이블 착석 상태 문자열이 연결된다.
- [ ] 가격·효과가 확정되지 않은 아이템·회복 기능에 `미확정` 안내 문구가 나타나지 않는다.
- [ ] 런타임 문자열 데이터와 빌드 리비전을 함께 기록한다.

- 한국어·영어 초안 작성
- 사용자 편집용 Google 스프레드시트 생성
