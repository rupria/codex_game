## 2. 프로그래밍 요청

### 개발·QA 치트

- GitHub Issue #35의 스테이지 통과, 지정 아이템 생성, 포커 카드 세팅을 구현한다.
- 스테이지 통과는 정상 승리·총알 정산·상점·전환 경로를 정확히 한 번 호출한다.
- 지정 아이템은 정상 인벤토리 획득 경로와 제한 규칙을 사용한다.
- 카드 세팅은 실제 카드 ID 8장, 중복 검증과 실제 포커 판정기를 사용한다.
- 치트는 `UNITY_EDITOR` 또는 `ENABLE_GAMEPLAY_CHEATS`에서만 포함하고 일반 WebGL·릴리스·`pub`에서는 활성화 경로를 제거한다.
- 치트 세션에는 워터마크와 `CheatUsed=true`를 기록하고 외부 기록·저장 업로드를 막는다.

### 예측 보상과 재화 분리

- 예측 제한 시간은 120초다.
- 스테이지 클리어 보상은 기본 재화, 예측 성공 보상은 일회성 재화로 지급한다.
- 예측 성공 횟수는 현재 스테이지 안에서 집계하고 실패·무반응은 지급 대상에 포함하지 않는다.
- 두 재화는 별도 필드로 저장하며 합산 수량을 원본 데이터로 사용하지 않는다.
- 상품 구매 시 일회성 재화를 먼저 차감하고 부족분만 기본 재화에서 차감한다.
- 상점 이탈 시 남은 일회성 재화를 0으로 초기화한다.
- 캐릭터 사망 시 두 재화와 예측 집계를 초기화한다.
- 지급량은 조정 가능한 밸런싱 데이터로 구현하고 기존 0.5배 공식을 제거한다.
- 결과·상점 UI에는 재화 명칭 없이 서로 다른 아이콘과 숫자만 표시한다.

### 아이템·상점

- 1차 구현 ItemId는 IT-01 재장전, IT-02 밑장빼기, IT-03 바람잡이다.
- 가격은 각각 1, 2, 2다.
- 버린 카드는 미획득 풀에 즉시 넣고 같은 아이템 추첨 후보에 다시 포함한다.
- 바람잡이는 AI 개인 카드 중 무작위 1장을 현재 포커 라운드 동안 공개한다.
- 인벤토리 4칸, 동일 ID 최대 1개, 상점 구매 횟수 무제한을 적용한다.
- 패 확정 전 여러 보유 아이템을 연속 사용할 수 있게 하며 기본 라운드당 사용 제한은 두지 않는다.
- 보유 아이템과 총알은 현재 런 동안 이월하고 캐릭터 사망 시 초기화한다.
- AI 아이템 사용 로직은 구현하지 않는다.
- 상점은 스테이지 승리 후 확정 등장하고 `상점 이탈` 전까지 유지한다.
- 상점은 최대 4슬롯이며 회복 아이템을 포함하고 나머지 아이템은 균등 무작위로 구성한다.
- 체력 회복 아이템 가격은 총알 1개로 적용한다.

### 패배·스테이지별 AI·전환

- 플레이어 패배 시 별도 보상을 지급하지 않고 총알·예측 성공 횟수·인벤토리·스테이지 진행을 초기화한다.
- 재도전은 1스테이지부터 시작한다.
- AI HP는 1~3스테이지 모두 3으로 유지한다.
- AI 반응시간은 1스테이지 `1/2/3초`, 2스테이지 `0.95/1.90/2.85초`, 3스테이지 `0.90/1.80/2.70초`의 최소/일반/최대 기준을 사용한다.
- 유리한 카드 선택 확률은 1스테이지 60%, 2스테이지 63%, 3스테이지 66%로 적용한다.
- 정답·오답·놓침 확률은 전 스테이지 60%·20%·20%로 유지한다.
- 상점 이탈 시 스테이지 전환 연출을 시작하고 입력을 잠근다.
- 고정 초 수 대신 전환 연출의 실제 재생 완료 이벤트에서 다음 스테이지에 진입한다.
## 3. QA 요청

### 패배·AI·전환 회귀

- 패배 직후 보상이 0이며 현재 런 데이터가 초기화되는지 확인한다.
- 재도전 시 스테이지 번호 1, 양측 HP 3으로 시작하는지 확인한다.
- 스테이지별 반응시간 범위와 유리한 카드 선택 확률을 시드 고정 반복 테스트로 검증한다.
- 세 스테이지 모두 AI HP가 3인지 확인한다.
- 전환 연출 중 키보드·마우스 입력이 처리되지 않는지 확인한다.
- 연출 재생 완료 전에는 다음 스테이지가 시작되지 않고 완료 이벤트 이후 한 번만 시작되는지 확인한다.
### 예측 보상·재화 UI 회귀

- 스테이지 클리어 기본 재화와 예측 성공 일회성 재화가 별도 수량으로 기록되는지 확인한다.
- 예측 실패·120초 무반응·스테이지 패배에서는 일회성 재화가 지급되지 않는지 확인한다.
- 가격보다 일회성 재화가 적거나 같거나 많은 세 경우에 일회성 우선 차감이 정확한지 확인한다.
- 상점 이탈 시 남은 일회성 재화만 소멸하고 기본 재화는 유지되는지 확인한다.
- 사망 시 두 재화와 예측 집계가 모두 초기화되는지 확인한다.
- 일반 플레이 화면에서 `총알`, `일회성 총알`, `할리갈리`, `포커` 문자열이 노출되지 않는지 전체 씬을 검사한다.
- 두 재화를 색상 없이 아이콘 형태와 위치만으로 구분할 수 있는지 확인한다.
- 결과 UI는 기본 지급과 일회성 지급을 아이콘별로 분리해 표시한다.

### 아이템 회귀

- 버린 카드가 같은 재장전 또는 밑장빼기 추첨에서 다시 나올 수 있는지 시드 고정 테스트로 검증한다.
- 후보 부족·중복·풀 고갈 시 아이템과 카드 상태가 손상되지 않는지 확인한다.
- 바람잡이가 정확히 AI 카드 1장을 무작위 공개하고 라운드 종료 후 다시 숨김 상태로 초기화되는지 확인한다.
- 4개 보유, 동일 ID 재구매, 빈 슬롯, 여러 아이템 연속 사용과 스테이지 이월을 검증한다.
- AI가 어떤 스테이지에서도 아이템을 사용하지 않는지 확인한다.

### 치트 회귀

- 명령 중복 입력으로 보상·스테이지·상점이 중복되지 않는지 확인한다.
- 치트 카드 세팅 뒤에도 예측→AI 공개→포커 비교→피해→다음 라운드가 정상 진행되는지 확인한다.
- 일반 WebGL·릴리스·`pub` 빌드에서 F10, DEV UI, URL 파라미터와 콘솔로 치트를 열 수 없는지 확인한다.

## 4. PM 확인 및 제외사항

- 초기 콘텐츠 범위는 3스테이지로 관리한다.
- 플레이어가 `상점 이탈`을 선택할 때까지 상점을 유지한다.
- 미확정 항목은 별도 이슈로 분리하고 이번 구현에 임의 수치를 넣지 않는다.
- 미확정: 아이템 사용 제한 스테이지와 제한 수, 후순위 아이템 효과, 3스테이지 이후 종료 화면.
- 작업 PR·QA 결과에는 적용 명세를 `게임진행플로우_0.1.2.2`로 표시한다.
