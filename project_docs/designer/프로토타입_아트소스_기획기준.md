## 1. 기획 결정

- 임시 에셋 우선 개발 방식을 승인한다.
- 완성 아트 도착은 카드 펼치기부터 전투 종료까지의 코어 기능 착수 조건이 아니다.
- 프로토타입에서는 예술적 완성도보다 카드 정보 판독, 좌우 선택, 입력 결과와 상태 구분을 우선한다.
- 카드·화면·색상 규격은 첫 플레이 가능 빌드의 가독성 테스트 결과에 따라 조정할 수 있다.
- 실제 제작 담당자와 전달 일정은 PM이 별도로 지정한다.

## 2. 기준 화면

| 항목 | 프로토타입 기준 |
|---|---|
| 화면 비율 | 16:9 |
| 기준 RenderTexture | `960×540` |
| 확대 방식 | 정수 배율 우선, 비정수 배율에서는 레터박스 또는 선명도 보정 |
| 픽셀 필터 | Point / Nearest 계열 |
| 필수 검증 | 960×540 내부 화면, 1280×720 및 1920×1080 브라우저 표시 |
| 안전 영역 | 화면 가장자리에서 가로·세로 5% 안쪽 |

`640×360`은 카드의 문양·랭크·해골을 동시에 읽기 어려울 가능성이 있어 기본값으로 사용하지 않고 성능 대안으로만 남긴다.

## 3. 화면 정보 우선순위

1. 좌우 카드 더미의 해골 수와 현재 노출 카드
2. 카드의 랭크와 문양
3. 왼쪽·오른쪽 벨 선택 영역과 `Q`·`E` 안내
4. 중앙 카드 펼치기 영역과 `W` 안내
5. 플레이어·AI의 할리갈리 라운드 승수
6. 카드 펼치기 30초 제한 시간
7. 첫 공용 카드와 아직 공개되지 않은 두 번째 공용 카드 슬롯
8. 플레이어 획득 카드, HP와 후속 포커 정보

합계 숫자, 정답 더미 강조와 자동 계산 결과는 표시하지 않는다.

## 4. 카드 최소 규격

| 항목 | 기준 |
|---|---|
| 카드 원본 크기 | `64×90 px` |
| 보드 기본 표시 | 원본 1배 이상 |
| 카드 집중·선택 표시 | 원본 2배인 `128×180 px` 권장 |
| 외곽선 | 최소 2 px |
| 랭크·문양 영역 | 왼쪽 상단에 고정, 카드가 겹쳐도 식별 가능 |
| 해골 영역 | 카드 중앙, `1·2·3`을 개수와 배열로 구분 |
| 카드 뒷면 | 랭크·문양·해골 정보를 추론할 수 없는 공통 이미지 |

### 카드 앞면 배치

- 왼쪽 상단: 랭크 `A, 2~10, J, Q, K`
- 랭크 인접 영역: 문양 `스페이드, 클로버, 하트, 다이아몬드`
- 중앙: 할리갈리 판정용 해골 1~3개
- 가장자리: 선택·획득·비활성 효과가 카드 정보와 겹치지 않는 여백
- 좌우 더미에서 두 장이 겹칠 때 이전 카드의 랭크·문양·해골 수가 모두 가려지지 않도록 배치

## 5. 보드와 카메라 구성

- 카메라는 고정된 3/4 탑다운 구도를 사용한다.
- 화면 왼쪽과 오른쪽 카드 더미를 중심축 기준으로 대칭 배치한다.
- 각 더미에는 최대 2장만 노출하며, 겹침 간격은 카드 정보를 동시에 읽을 수 있게 유지한다.
- 첫 공용 카드는 상단 중앙에 공개하고 두 번째 공용 카드 슬롯은 할리갈리 단계 종료 전까지 뒷면 또는 잠금 상태로 표시한다.
- 중앙 하단에는 카드 펼치기 입력 영역을 두고 `W`를 항상 확인할 수 있게 한다.
- 왼쪽과 오른쪽 벨은 각 더미에 시각적으로 연결하고 `Q`·`E` 표기를 유지한다.
- 개인 카드 선택 단계에서는 보드보다 선택 카드 영역을 우선해 확대한다.

## 6. 프로토타입 기능 색상

| 기능 | 기준 색상 | 용도 |
|---|---|---|
| 배경 | `#11141A` | 화면 기본 배경 |
| 보드 | `#242B35` | 카드와 UI가 놓이는 영역 |
| 카드 바탕 | `#E8E1D0` | 카드 앞면 |
| 기본 글자 | `#1A1B20` | 랭크·해골·본문 |
| 탐색 하이라이트 | `#51D6E5` | 마우스 오버, Q·E 이동 |
| 선택·확정 가능 | `#F5C451` | 선택 카드, 확정 버튼 활성화 |
| 오답·시간초과 | `#E55353` | 판정 이후 실패 피드백 |
| HP | `#D84A5B` | 생명력 표시 |
| 비공개·잠금 | `#39424E` | 카드 뒷면, 비활성 슬롯 |

- 합계 3 여부는 색상으로 미리 알려주지 않는다.
- 문양은 색상만으로 구분하지 않고 서로 다른 실루엣을 반드시 사용한다.
- 오답 색상은 입력 판정 이후에만 표시한다.

## 7. 프로토타입 필수 에셋

### P0 기능 검증용

- 카드 앞면 바탕 1종, 뒷면 1종
- 문양 아이콘 4종
- 랭크 글리프 13종
- 해골 표시 1·2·3종
- 벨 기본·하이라이트·입력·오답 상태
- 좌우 카드 더미 영역과 중앙 펼치기 영역
- 카드 선택·해제·확정 가능·비활성 상태
- 플레이어·AI 할리갈리 라운드 승수와 HP 표시
- 공용 카드 공개·잠금 슬롯
- 30초 및 1분 제한 시간 표시

### 후순위 교체 가능

- 캐릭터 완성 일러스트와 초상화
- 고급 파티클·셰이더·화면 흔들림
- 세부 배경 오브젝트와 장식
- 최종 폰트와 사운드 세트
- 아이템 완성 아이콘

## 8. 파일 전달 기준

- 권장 경로: `Assets/Art/Prototype/{Cards,Board,UI,FX,Characters}`
- 파일명은 영문 소문자 `snake_case`를 사용한다.
- 상태 변형은 `{asset}_{state}` 형식으로 구분한다.
  - 예: `bell_idle`, `bell_hover`, `bell_wrong`
  - 예: `card_back`, `card_front_base`, `skull_01`
- 원본 Aseprite 파일과 출력 PNG의 기본 이름을 동일하게 유지한다.
- 스프라이트는 투명 배경 PNG로 전달하고 임의 리사이즈를 적용하지 않는다.
- 외부·AI 생성 소스는 `파일명, 출처, 작성자·도구, 라이선스, 수정 여부, 공개 빌드 사용 가능 여부`를 기록한다.
- 권한이 확인되지 않은 소스는 임시 로컬 테스트에만 사용하고 공개 빌드에서 제외한다.

## 9. 기획 수용 기준

- [ ] 기준 화면에서 카드의 랭크·문양·해골 수를 합계 표시 없이 구분할 수 있다.
- [ ] 좌우 각 더미의 두 장을 동시에 보고 해골 합계를 직접 판단할 수 있다.
- [ ] 카드 더미와 `Q`·`E` 벨 입력 방향이 혼동되지 않는다.
- [ ] 중앙 펼치기 영역과 `W` 입력을 첫 화면에서 확인할 수 있다.
- [ ] 첫 공용 카드와 비공개 두 번째 공용 카드 슬롯을 구분할 수 있다.
- [ ] 하이라이트는 탐색·선택 상태만 표현하고 정답을 노출하지 않는다.
- [ ] 오답·시간초과 피드백은 판정 이후에만 나타난다.
- [ ] 개인 카드 선택 단계에서 선택·해제·3장 확정 가능 여부가 구분된다.
- [ ] 임시 에셋을 완성 에셋으로 교체해도 게임 판정 로직이 변경되지 않는다.
- [ ] 공개 빌드에 포함되는 모든 외부 소스의 사용 권한을 확인할 수 있다.

## 10. 역할별 후속 작업

- 기획: 첫 플레이 가능 빌드에서 카드 판독 시간, 입력 방향 혼동과 정보 과부하를 확인한다.
- 프로그래머: 임시 에셋 교체가 가능한 프레젠테이션 구조와 기준 화면을 적용한다.
- QA: 960×540 기준 가독성, 브라우저 확대, 키보드·마우스 입력 피드백을 검증한다.
- PM: 실제 아트 제작 담당자, 규격 확정 목표일과 첫 완성본 전달 목표일을 지정한다.
- 아트 협업자: 본 규격에 맞는 Aseprite 원본과 PNG, 라이선스 정보를 함께 전달한다.
