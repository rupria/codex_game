## 1. 여러 PC 작업환경과 Git 충돌 방지

- 문제: Google Drive 안의 Git 작업공간이 비정상 인덱스와 중복 파일 상태를 보였고, 데스크톱·노트북의 동시 미푸시 작업은 변경 유실 위험이 있었다.
- Codex 활용: 저장소와 Drive 역할을 감사하고, 로컬 Git 개발공간·Drive 문서 원본·GitHub 동기화·릴리스 bundle의 경계를 문서화했다.
- 사람이 결정한 내용: Git·코드·테스트·빌드는 로컬 저장소에서만 수행하고, Drive는 Obsidian 원본과 공유 복구본에만 사용하며, 두 PC에 같은 브랜치의 미푸시 변경을 동시에 남기지 않는다.
- 결과 기록: `77fee00`, `468750b`, `e46a9e9`, `6da884e`; 현재 11개 worktree는 `dev` 주 작업공간 하나로 정리했고 정리 전 상태는 `G:\내 드라이브\codex_game\shared\recovery\codex_game_dev_consolidation_recovery_20260810-211341.zip`에 단일 복구본으로 보존했다.

## 2. 첫 30초에 이해되는 게임 흐름

- 문제: 규칙은 동작해도 첫 화면, 카드 공개 순서, 벨 입력, 획득 결과와 포커 전환이 한눈에 이해되지 않았다.
- Codex 활용: 기획 변경을 상태 머신·입력 잠금·프레젠테이션 계층으로 분해하고 시작 화면, 가이드, 4장 순차 공개, 타이머와 단계 전환을 구현·테스트했다.
- 사람이 결정한 내용: 시작 화면은 `START`와 `GUIDE`, 기본 조작은 `Q/W/E`, 한 번의 펼치기 입력은 4장 교차 공개, 최대 12회, 할리갈리 목표는 `3→2→2`로 확정했다.
- 결과 기록: 기획 `77c9917`, 구현 `a61636e`, 아트·조명 `55da9c0`, UI 보완 `3dbbff9`; [게임진행플로우 0.1.0](../../designer/게임진행플로우_0.1.0.md)과 `PlayableGameSession`, `GuideModalPanel`에서 확인할 수 있다.

- 결과 기록: `6f26cc8`, `3dbbff9`, `2069886`; 현재 `HalliLowerHudRenderer`, `HalliPileOverlapLayout`, `PokerTableLayout`과 관련 스모크 테스트에 남아 있다.

## 5. 아트 제작과 런타임 연결

- 문제: 임시 UI와 카드 아트는 정보 우선순위와 웨스턴 분위기가 약했고, 여러 버전 브랜치에 최종·원본·런타임 자산이 나뉘어 있었다.
- Codex 활용: Aseprite·이미지 생성 기반의 카드, 하트, 밧줄, 상점, 재화, 조커 자산을 제작하고 Unity 런타임 슬롯과 `.meta`를 연결했다. `dev` 통합 중에는 새 조커 2개와 기존 카드가 공유하던 Unity GUID도 찾아 분리했다.
- 사람이 결정한 내용: 웨스턴 살룬 방향, 텍스트를 굽지 않는 재화 UI, 승인된 J/Q/K와 조커, 플레이어·AI 색상, 기존 `dev` GUID 우선 보존을 확정했다.
- 결과 기록: `14230e3`, `4bfe672`, `aa7ffca`, 통합 `244cc2f`; `Assets/Art/Prototype`의 런타임 자산과 `ArtReferences`의 카탈로그·원본으로 확인할 수 있다.

## 6. 해골 분포와 체력 기반 페어 보정

- 문제: 카드 ID 구간으로 해골 수를 배정하면 해골 3 카드가 지나치게 많았고, 초반 포커 패가 무작위 고카드에 치우칠 수 있었다.
- Codex 활용: 52장 명시 테이블, 문양별 희귀 해골 3 검증, 획득 후보의 페어 추천과 랜덤 보충 정책을 구현하고 기존 포커 분포 보정과 충돌하지 않도록 통합했다.
- 사람이 결정한 내용: 해골 수는 `1=30장, 2=18장, 3=4장`, 문양마다 해골 3은 1장, 양측 잔여 체력 합이 5 이상일 때 페어 보정을 켜고 보충 확률은 85%로 사용한다.
- 결과 기록: `98c20cc`, `ba24a7e`; `PrototypeSkullPolicyTests`, `PrivateCardDistributionTests`, `PairAssistSelectionPolicy`로 확인할 수 있으며 전체 C# 스모크 테스트가 통과했다.

## 7. 조커 규칙 0.1.2.3과 정보 공개 순서

- 문제: 조커의 지급 대상·확률·패 구성 방식과 두 번째 공용 카드 공개 시점이 불명확하면 재판정, 정보 노출, 실카드 중복 같은 규칙 오류가 생길 수 있었다.
- Codex 활용: 참가자별 독립 지급 판정, 선택 세션 재진입 차단, 공용 카드 선결정, 합법 족보 대체 탐색, AI 비공개 선택과 QA 치트를 코드·다국어 문자열·자동 테스트로 함께 구현했다. 기존 체력 기반 페어 보정과 충돌한 분배 코드는 두 규칙이 함께 동작하도록 통합했다.
- 사람이 결정한 내용: 승자의 최종 획득 카드가 4장 이상일 때만 참가자별 독립 10% 판정을 1회 수행하고, 조커는 개인 카드 한 장으로 계산한다. 1라운드는 3장 직접 선택, 이후는 2장 선택 뒤 1장 보충이며, 두 번째 공용 카드는 개인 카드 선택 전에 공개·고정한다.
- 결과 기록: 기능 `5374350`, 테스트 `5232923`; `JokerAwardResolver`, `PokerJokerHandResolver`, `PrivateCardSelectionSession`, `PokerJokerRulesTests`에서 확인할 수 있다. 구현 완료 보고서는 활성 문서에서 제거했고 원본 이력은 Git 및 단일 복구 bundle에 남겼다.
