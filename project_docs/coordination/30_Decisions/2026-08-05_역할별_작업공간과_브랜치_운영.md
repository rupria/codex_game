## 브랜치 운영

- 일반 개발, 기획 연계, 문서화와 QA의 우선 기준 브랜치: `dev`
- 통합 빌드와 실행 파일 또는 배포 산출물 브랜치: `pub`
- 사용자의 별도 요청이 없으면 `pub`에 커밋, 푸시 또는 병합하지 않는다.
- `dev` 검증 통과는 `pub` 반영의 자동 승인을 의미하지 않는다.
- `pub` 반영 전에는 통합 빌드, 실행 파일, 알려진 제한과 회귀 범위를 별도로 확인한다.
- 검증 기록에는 대상 브랜치와 커밋 SHA를 남긴다.

## 역할별 Git 제한

- 프로그래머는 `obsidian\rules\programer\프로그래머_업무_규칙.md`에 따라 변경 범위를 확인하고 목적별로 커밋한다.

- 다른 작업자의 미커밋 변경을 포함해 브랜치를 이동하거나 커밋하지 않는다.
- 강제 푸시, 강제 초기화와 이력 재작성은 합의 없이 진행하지 않는다.
