## 3. 최신 게임 진행 규칙

### 3.1 할리갈리 판정

- 왼쪽 벨과 오른쪽 벨은 각각 대응하는 한쪽 카드 더미만 판정한다.
- 한쪽 더미의 판정 카드는 최대 2장이다.
- 반대쪽 더미와 합산하지 않으며 `1 + 1 + 1`은 인정하지 않는다.
- 같은 문양의 해골 `1 + 2`가 성립하면 두 장을 모두 획득한다.
- 해골 3 성공 시 펼치기 단계에 노출된 해당 해골 3 카드 한 장만 획득한다.
- 양쪽 조건이 동시에 맞으면 먼저 누른 벨을 정답으로 처리한다.
- 플레이어와 AI 입력이 동시 판정 범위에 들어오면 플레이어를 우선한다.

### 3.2 카드 공개와 입력

- 공개 순서는 `플레이어 왼쪽 → AI 왼쪽 → 플레이어 오른쪽 → AI 오른쪽`이다.
- 승패가 난 직후 다음 진행에 2초 펼치기 잠금을 1회만 적용한다.
- 2초 잠금이 끝난 뒤에는 카드 공개 중에도 벨 입력을 받을 수 있다.
- 카드는 앞면 전환 완료부터 판정 대상이다.
- 공개 중 벨 결과가 확정되면 남은 카드 공개를 즉시 중단하고 다음 할리갈리 라운드로 이동한다.
- 미선택 카드 더미의 최상단 카드는 해당 더미 맨 아래로 이동한다.

### 3.3 시간·종료·카드 부족

- 2초 잠금이 끝나면 30초 벨 입력 제한 타이머를 시작한다.
- 제한 시간 초과와 오조작·오답 벨은 해당 할리갈리 라운드의 패배 1회다.
- 위 사유로 상대가 승리하면 승리 1회만 기록한다.
- 패배 참가자가 이전 라운드에서 정상 획득한 카드는 현재 전투의 포커 라운드까지 유지한다.
- 기존 획득 카드를 빼앗거나 상대에게 별도의 보상 카드 선택 단계를 제공하지 않는다.
- 할리갈리 단계는 최대 12회, 1회당 최대 4장 배분 제한을 유지한다.
- 전투 라운드 진행 중 미획득 카드풀 재셔플은 하지 않는다.
- 펼치기 저장소가 4장 미만이어도 남은 카드가 있으면 진행한다.
- 다음 카드 공개가 필요하지만 펼칠 카드가 없으면 할리갈리 단계를 즉시 종료한다.

### 3.4 개인 카드 구성

- 할리갈리 패자도 정상 획득 카드를 개인 저장소에 유지한다.
- 개인 획득 카드가 3장을 초과하면 플레이어와 AI 모두 포커에 사용할 3장을 직접 선택한다.
- 기존 `3 → 2 → 2` 직접 선택 규칙을 유지한다.
- 단계 종료 시 3장 미만이면 미획득 카드풀에서 시드 기반 무작위 지급으로 정확히 3장을 만든다.
- 카드 펼치기에 사용하지 못한 잔여 카드와 필드의 미획득 카드도 무작위 보충 후보에 포함한다.
- 개인 카드 저장소는 전투 라운드가 끝나면 초기화하고 다음 전투 라운드는 새 52장 덱과 새 시드로 시작한다.

### 3.5 공개 빌드 코인·아이템 범위

- 현재 공개 빌드는 코인의 보유 수치만 카운트하고 표시한다.
- 아이템 보상 수, 아이템 효과와 `미확정` 개발 안내 문구는 공개 화면에 노출하지 않는다.
- 아이템 보상·효과는 현재 공개 빌드 구현 범위에서 제외한다.
- 아래 아이템 사용 순서 규칙은 향후 아이템 시스템 활성화 시 적용할 기준이며, 현재 공개 빌드에서는 아이템 사용 단계를 호출하지 않는다.

### 3.6 포커·아이템·예측

- 개인 카드 3장과 커뮤니티 카드 2장, 정확히 5장을 모두 사용한다.
- 포커 동률은 최신 명세의 랭크 비교 후 문양 비교를 적용한다.
- A는 기본 14이며 `A-2-3-4-5`에서만 1로 처리한다. 중간 순환 조합은 스트레이트가 아니다.
- 아이템은 승패 예측 전에만 사용한다.
- 기존 `카드 변경 시 재예측` 규칙은 폐기한다.
- 모든 카드 변경이 끝난 최종 카드 상태에서 승패 예측을 한 번 진행한다.
- 승패 예측 제한 시간은 2분이다.

## 4. UI 다국어 구현 요청

### 4.1 데이터 구조

- 코드에서는 숫자 ID가 아니라 `UI_MAIN_START` 같은 의미형 Key를 사용한다.
- Google Sheet의 `ID`는 사람이 행을 찾는 순번일 뿐 코드 참조값이 아니다.
- 하나의 UTF-8 CSV에 `Key`, `ko`, `en` 열을 둔다.
- Google Sheet를 번역 기준 원본으로 하고, 저장소 CSV는 내보낸 실행 산출물로 취급한다.
- 권장 런타임 경로: `Assets/StreamingAssets/Localization/ui_strings.csv`

### 4.2 런타임 동작

- 시작 시 CSV를 비동기 로드한다. WebGL의 `StreamingAssets`는 `UnityWebRequest`를 사용한다.
- 기본 언어는 한국어다.
- 메인 화면에서 `한국어 / English`를 선택할 수 있게 한다.
- 언어 변경은 재시작 없이 현재 화면과 이후 화면에 즉시 반영한다.
- 언어 설정을 로컬에 저장하고 다음 실행에서 복원한다.
- 누락 값은 `현재 언어 → en → [MISSING:KEY]` 순서로 대체한다.
- 누락 Key 경고는 Key별 1회만 기록한다.

### 4.3 계층 분리

- Presentation 계층의 사용자 노출 문장을 모두 Key 조회로 전환한다.
- Core/Application 계층은 완성된 영어·한국어 문장을 보관하지 않는다.
- `PrototypeHalliSession`의 `_statusMessage` 형태를 `StatusKey + StatusArgs`로 교체한다.
- 카드 배분 상태의 `actor`, `side`, `step` 등은 변수로 전달하고 Presentation에서 최종 번역한다.

### 4.4 폰트와 화면

- 한글·라틴·숫자·키보드 기호·카드 문양이 포함된 라이선스 확인 폰트를 명시적으로 사용한다.
- 960×540 WebGL에서 한국어와 영어 모두 버튼, HUD, 가이드, 상태 문장의 잘림·겹침이 없어야 한다.
- `W`, `Q/E`, `1/2`, `ENTER`, `ESC`와 `CODEX GAME` 브랜드명은 번역하지 않는다.

## 5. 현 구현에서 반드시 대조할 충돌

1. `Player exceeded the 30-second flip limit.`
   - 현재 구현은 펼치기 제한으로 보이나 최신 기준은 2초 잠금 후 30초 벨 입력 제한이다.
2. 4장 전체 공개 후 벨 판정
   - 최신 기준은 2초 잠금 후 공개 도중에도 입력 가능하며 앞면 전환 완료 카드만 판정한다.
3. 오조작 후 보상 카드 선택 관련 상태와 문구
   - 제거한다. 상대 승리 1회만 기록하고 패배 참가자의 기존 획득 카드는 유지한다.
   - 기존 획득 카드를 빼앗거나 별도의 보상 카드 선택 단계로 이동하지 않는다.
4. 승패 예측 1분 및 카드 변경 시 재예측
   - 예측 2분, 아이템 선사용, 재예측 폐기로 교체한다.
5. 전투 중 미획득 카드 재셔플
   - 재셔플하지 않고 카드 소진 시 할리갈리 단계를 종료한다.
6. `Coin bonus values and item effects are pending design.` 및 아이템 보상 표시
   - 공개 빌드에서 제거한다.
   - HUD와 스테이지 종료 화면은 코인 보유 수치만 표시한다.

구버전 영문을 단순히 한국어로 바꾸지 말고 최신 상태 전이와 함께 교체한다.
