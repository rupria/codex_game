# 협업 및 동시 작업 규칙

- 목적: Google Drive 공유 문서와 Git 저장소에서 여러 작업자가 동시에 진행할 때 변경 손실과 충돌을 방지한다.
- 적용 범위: `obsidian\core` 문서, `obsidian\rules` 규칙, 게임 코드, Git 작업과 Google Drive 동기화 파일 전체
- 반드시 할 것:
  - 작업 직전에 대상 파일과 Git 상태를 다시 확인한다.
  - 작업 대상이 코드인지 문서인지 판단한다. 코드는 Git, 문서는 Drive에서 작업하는 것을 기본으로 한다.
  - 코드가 아닌 업무라도 사용자가 Git 공유가 필요하다고 지정했거나 공동 검토·이력 관리·자동화에 Git이 필요한 경우에는 Git 공유 대상으로 분리할 수 있다.
  - 비코드 업무를 Git에 공유할 때는 Drive 기준 원본 여부를 명시하고, 동일 문서를 Drive와 Git에서 독립적으로 수정하지 않는다.
  - 비코드 Git 공유는 목적별 단독 커밋으로 처리하고 다른 역할의 진행 중 변경을 포함하지 않는다.
  - Obsidian은 `G:\내 드라이브\codex_game\obsidian`만 Vault로 연다.
  - Git 명령은 반드시 각 PC의 `C:\sk-encoa\codex_game` 저장소 루트에서 실행한다.
  - 다른 PC는 `G:\내 드라이브\codex_game\multi_pc\SETUP_OTHER_PC.ps1`로 로컬 저장소를 구성한다.
  - `G:\내 드라이브\codex_game` 최상위의 예전 Git 사본과 `.git` 잠금·인덱스에는 손대지 않는다.
  - 기존 변경은 다른 작업자의 작업일 수 있다고 가정하고 보존한다.
  - 수정 범위를 작게 유지하고 관련 없는 변경을 포함하지 않는다.
  - 동시 변경이 발견되면 파일, 모듈 또는 브랜치 단위로 작업 범위를 분리한다.
  - 완료 시 변경 범위, 검증 결과, 커밋·푸시·동기화 여부와 다음 행동을 남긴다.
- 하지 않을 것:
  - 다른 작업자의 변경을 임의로 덮어쓰기, 삭제, 이동 또는 되돌리기
  - 확인되지 않은 변경을 자신의 작업과 함께 커밋하기
  - 합의 없이 강제 푸시, 강제 초기화 또는 이력 재작성하기
  - 기준 원본이 불명확한 문서를 여러 위치에서 독립적으로 수정하기
  - 단순 동기화 편의를 이유로 Drive 문서 전체를 Git 저장소에 중복 적재하기
- 예외: 치명적 장애 대응처럼 즉시 변경이 필요한 경우에도 대상과 영향 범위를 먼저 확인하고, 사후에 변경 이유와 결과를 기록한다.

## 빌드 버전과 리비전

- 공식 빌드는 선행 0이 없는 `Major.Minor.Patch` 제품 버전을 사용한다.
- Major 증가 시 Minor·Patch를 0으로, Minor 증가 시 Patch를 0으로 초기화한다.
- 공식 배포한 버전은 수정·덮어쓰기하지 않으며 변경분은 새 버전으로 발행한다.
- 공유 시 제품 버전, 전체 Git SHA, SpecRevision, ArtifactSHA256과 공개 URL을 함께 적는다.
