# 빌드 버전 관리 정책

> 공식 빌드는 제품 버전과 코드·명세·산출물 해시를 함께 기록하며, 한 번 배포한 버전은 수정하지 않는다.

## 식별 규칙

- 제품 버전: `Major.Minor.Patch`
- 허용 형식: `0.1.0`, `1.0.0`, `2.3.14`
- 금지 형식: `01.0.0`, `1.02.0`, `1.0.03`
- Major 증가 시 Minor와 Patch는 `0`, Minor 증가 시 Patch는 `0`으로 초기화한다.
- Git 태그: `vMajor.Minor.Patch`

## 공식 빌드 필수값

- `ProductVersion`: 제품 버전
- `GitCommit`: 전체 Git commit SHA
- `GitShortCommit`: 표시용 SHA 앞 12자
- `SpecRevision`: 명세 스냅샷 목록의 SHA-256
- `ArtifactSHA256`: 실제 빌드 파일의 SHA-256
- 공개 플레이 URL과 생성·검증 시각

리비전과 해시는 추적 정보이며 제품 버전을 대신하지 않는다.

## 불변 배포 원칙

- 공식 배포된 버전의 파일과 내용은 절대 변경하거나 덮어쓰지 않는다.
- 코드, 명세, 설정 또는 빌드 산출물이 바뀌면 반드시 새 버전으로 배포한다.
- 같은 제품 버전인데 산출물 해시가 다르면 정상 배포로 인정하지 않는다.
- 보존 위치: `G:\내 드라이브\codex_game\multi_pc\versioned_builds\vMajor.Minor.Patch`

## 업무 분담

- 기획: 변경 내용과 수용 기준을 확정하고 명세 범위를 식별한다.
- 프로그래머: 깨끗한 Git 커밋에서 빌드하고 식별자를 생성한다.
- QA: 식별자와 실제 산출물·공개 URL의 일치 여부를 검증한다.
- PM: 버전 증가 수준을 결정하고 출시 기록 및 승인 상태를 관리한다.

## 현재 상태

- 공식 제품 버전: `UNRELEASED`
- 첫 공개 후보 권장값: `0.1.0`

Git 저장소의 `VERSIONING.md`와 `tools/New-VersionedBuild.ps1`가 구현 기준이다.
