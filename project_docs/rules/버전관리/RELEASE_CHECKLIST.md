# 버전 배포 체크리스트

## 발행 전

- [ ] PM이 Major / Minor / Patch 증가 사유와 다음 버전을 승인했다.
- [ ] 버전 값에 선행 0이 없고 초기화 규칙을 지켰다.
- [ ] Git 작업 트리가 깨끗하며 대상 커밋이 `dev`에 push되어 있다.
- [ ] 적용할 기획·수용 기준과 Drive 문서가 확정·동기화되었다.
- [ ] 브라우저 웹 빌드가 성공했다.

## 패키징

- [ ] `tools/New-VersionedBuild.ps1`로 새 버전 폴더를 생성했다.
- [ ] 매니페스트에 제품 버전과 전체 Git SHA가 기록되었다.
- [ ] 명세 스냅샷과 `SpecRevision`이 생성되었다.
- [ ] 빌드 파일의 `ArtifactSHA256`이 생성되었다.
- [ ] 기존 버전 폴더를 수정하거나 덮어쓰지 않았다.

## QA 및 공개 링크

- [ ] QA가 매니페스트 식별자와 테스트 대상이 같은지 확인했다.
- [ ] 시크릿 창에서 승인·초대 없이 공개 HTTPS 링크에 접속했다.
- [ ] 조작법과 실행 방법을 확인하고 핵심 플레이 루프를 완료했다.
- [ ] 지원 브라우저·입력 환경과 검증 시각을 기록했다.
- [ ] 같은 제품 버전의 산출물 해시가 이전 기록과 다르지 않다.

## 승인 후

- [ ] QA 판정과 잔여 위험을 PM이 확인했다.
- [ ] 사용자 승인 후 `vMajor.Minor.Patch` 태그 및 `pub` 통합을 진행했다.
- [ ] 공개 URL, 버전, 전체 Git SHA, SpecRevision과 ArtifactSHA256을 출시 기록에 남겼다.
- [ ] 공식 버전 폴더를 불변 기록으로 보존했다.
