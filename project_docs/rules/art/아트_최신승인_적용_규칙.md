# 아트 최신 승인 적용 규칙

- 목적: 구형 인계서·좌표·패키지가 최신 사용자 승인 화면을 덮어쓰는 회귀를 차단한다.
- 적용 범위: 아트 제작, UI 배치, Unity 런타임 연결, 아트 인계서, 이슈 코멘트, 빌드 게이트 전체.
- 마지막 검토일: 2026-08-24

## 기준 우선순위

1. 가장 최근 사용자가 직접 승인하거나 수정 지시한 이슈 코멘트·첨부 이미지
2. 최신 `00_기획_현재기준`과 최신 번호의 기획 리비전
3. 위 승인에 맞춰 작성된 현재 아트·프로그래머 인계서
4. 과거 인계서·과거 시안·보관 자산

작성 시각이 더 늦다는 이유만으로 AI가 만든 인계서나 자동 코멘트를 사용자 승인보다 위에 두지 않는다. 서로 충돌하거나 어떤 항목이 최신인지 판단할 수 없으면 적용·커밋·푸시·빌드를 중단하고 사용자에게 확인한다.

## 작업 시작 전 필수 기록

- 이슈 번호와 최신 승인 코멘트 URL
- 승인 시각(UTC)과 기준 Git SHA
- 활성 패키지·런타임 파일·Unity 슬롯
- 이번 승인으로 폐기되는 코멘트·문서·좌표·패키지
- 반드시 존재해야 하는 값과 다시 나타나면 안 되는 구형 값

이 기록은 `programer/CodexGame/ArtReferences/RuntimeBindingTools/latest_approved_art_contracts.json`에 추가 또는 갱신한다. 같은 이슈에는 활성 계약을 하나만 둔다.

새 아트·UI 작업은 예외 없이 이 등록부를 갱신해야 한다. 등록부에 최신 승인 출처가 없거나, 같은 이슈의 활성 계약이 두 개이거나, 승인보다 오래된 좌표·파일명이 다시 나타나면 빌드 게이트를 실패시킨다.

## 적용 및 검증

- 최신 화면을 구현하는 코드와 폐기 값을 거부하는 게이트를 같은 커밋에서 수정한다.
- 검증은 `requiredTokens`의 존재와 `forbiddenTokens`의 부재를 모두 확인한다.
- 이슈 본문 자체가 사용자의 요청과 첨부 이미지를 포함하면 `human-issue-and-image`, 후속 승인 코멘트가 기준이면 `human-issue-comment-and-image`로 기록한다.
- 새 PNG가 필요한 경우 승인 원본은 보관하되 런타임 활성 경로에는 최신 패키지만 연결한다.
- Unity 자동 재직렬화 파일과 관계없는 미커밋 파일을 의도 커밋에 포함하지 않는다.
- 스모크 테스트, 아트 런타임 게이트, Unity 컴파일·빌드, 실제 화면 확인을 순서대로 수행한다.

## 이슈 코멘트 규칙

- `최종`, `확정`, `승인` 표현은 사용자 승인 URL을 함께 제시할 때만 사용한다.
- 과거 기준을 무효화할 때는 무효 대상 URL과 대체 승인 URL을 모두 적는다.
- 구현 코멘트에는 확인 버전, 전체 SHA, 런타임 연결 경로와 남은 프로그래머 작업을 기록한다.
- AI가 작성한 구현·인계 코멘트만으로 사용자 승인 상태를 새로 만들지 않는다.

## 회귀 발생 시

- 회귀 코멘트를 삭제해 이력을 감추지 않고 `무효/대체됨` 정정 코멘트를 남긴다.
- 회귀 원인, 잘못 선택한 기준, 대체 기준, 재발 방지 게이트를 한 커밋에 기록한다.
- 해당 화면만 고치는 데 그치지 않고 공통 계약 레지스트리와 검증 규칙을 갱신한다.
