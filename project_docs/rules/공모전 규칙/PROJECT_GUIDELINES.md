## 필수 제출 형식과 플레이 링크

다음 조건은 선택 사항이 아니라 제출 필수 조건이다.

- 현장에서 심사위원이 직접 플레이할 수 있는 게임을 준비한다.
- 별도 설치 없이 브라우저에서 바로 실행되는 웹 빌드로 제출한다.
- 심사위원이 직접 플레이할 수 있는 공개 게임 링크를 반드시 제출한다.
- 플레이 링크는 심사 기간 전체에 걸쳐 접속 가능해야 한다.
- 초대, 개별 승인, 지역 제한과 유료 결제 없이 접근하고 플레이할 수 있어야 한다.
- 로그인이 불가피하면 심사용 테스트 계정과 사용 방법을 함께 제공한다.
- 링크를 연 직후 확인할 수 있는 위치에 조작법과 실행 방법을 안내한다.

위 조건을 충족하지 못하는 빌드는 제출 후보로 승인하지 않는다.

## 선택 제출과 가산점

아래 항목은 제출 필수 조건이 아니라 선택 가산점 항목이다. 필수 웹 빌드와 플레이 링크의 완성도를 낮추면서까지 우선하지 않는다.

### 3분 이내 데모 영상

- 실제 플레이가 포함된 3분 이내 영상을 선택 제출할 수 있다.
- 영상에는 게임 소개, 실제 플레이와 핵심 기능을 포함한다.
- 게임의 코어 재미와 조작 흐름이 짧고 명확하게 보이도록 구성한다.

### Codex 활용 설명

- Codex와 게임을 만든 과정을 선택 제출 자료로 설명하면 가산점을 받을 수 있다.
- Codex를 사용한 영역, 구현한 기능, 해결한 문제와 사람이 직접 결정한 부분을 구분한다.
- 근거는 문제 → Codex 활용 → 사람이 결정한 내용 → 결과 기록에서 수집한다.

## 최우선 원칙

아래 세 조건 중 하나라도 충족하지 못하는 아이디어나 기능은 채택하지 않는다.

### 1. 코어 플레이 자체가 재미있어야 한다

- 설명, 스토리, 그래픽을 제거해도 핵심 행동과 결과의 반복이 재미있어야 한다.
- 플레이어의 선택이 즉시 이해 가능한 피드백과 의미 있는 결과를 만든다.
- 첫 30초 안에 핵심 조작과 목표를 이해할 수 있게 한다.
- 3분 안에 긴장, 숙련, 발견 또는 웃음 중 하나 이상의 감정 곡선을 만든다.
- 콘텐츠 양으로 약한 코어 루프를 감추지 않는다.

검증 기준: 처음 보는 플레이테스터가 설명 없이 실행하고, 핵심 목표를 이해하며, 한 번 더 플레이하고 싶다는 반응을 보이는가?

### 2. 외부 공개와 플레이에 제약이 없어야 한다

- 브라우저에서 설치 없이 바로 실행되는 웹 빌드로 제공한다.
- 심사 기간 동안 공개 URL로 안정적으로 접속할 수 있게 한다.
- 승인, 초대, 지역 제한, 유료 결제 없이 플레이할 수 있게 한다.
- 로그인이 불가피하다면 심사용 테스트 계정과 명확한 접속 방법을 제공한다. 가능하면 로그인 자체를 없앤다.
- 이미지, 음원, 폰트, 코드, 데이터, AI 생성물 등 모든 구성 요소의 공개·배포 권리를 확인하고 기록한다.
- 비밀 키는 클라이언트에 포함하지 않으며, 외부 API 장애나 비용 한도 때문에 기본 플레이가 막히지 않게 한다.
- 조작법과 실행 방법을 게임 화면 및 제출 설명에 함께 제공한다.

검증 기준: 새 브라우저의 시크릿 창에서 링크 하나만으로 첫 플레이를 완료할 수 있는가?

### 3. 개발 과정에서 Codex를 실질적으로 활용한다

- Codex를 단순 질의 도구가 아니라 기획 검증, 프로토타이핑, 구현, 테스트, 디버깅, 리팩터링의 개발 파트너로 사용한다.
- 중요한 작업마다 `문제 → Codex 활용 → 사람이 결정한 내용 → 결과`를 간단히 기록한다.
- 생성된 코드는 사람이 검토하고, 실행·테스트 결과로 검증한 뒤 반영한다.
- 플레이 재미와 제품 방향에 관한 최종 판단은 플레이테스트 증거를 바탕으로 사람이 내린다.
- 기존 프로젝트를 활용할 경우 챌린지 기간에 새로 개발한 범위를 명확히 구분한다.

검증 기준: Codex가 구현한 기능, 해결한 문제, 사람이 직접 결정한 부분을 구체적인 사례로 설명할 수 있는가?

## 공모전 적합성 보조 원칙

공식 심사 기준도 개발 우선순위에 반영한다.

1. **Playability** — 실제로 안정적으로 작동하는가?
2. **Originality** — 아이디어와 플레이 방식이 독창적인가?
3. **Codex Collaboration** — Codex를 효과적으로 활용했는가?
4. **Release Potential** — 향후 Hive 등을 통해 서비스로 확장할 수 있는가?
5. **Presentation** — 게임과 개발 과정을 짧고 명확하게 시연·설명할 수 있는가?

기능 우선순위는 원칙적으로 다음 순서를 따른다.

`코어 재미 > 실행 안정성 > 접근성·공개 가능성 > 독창성 강화 > 연출·콘텐츠 양`

## 기능 채택 체크리스트

새 기능은 아래 질문에 모두 답할 수 있을 때만 개발한다.

- 이 기능이 코어 플레이의 선택, 피드백 또는 반복 욕구를 강화하는가?
- 공개 웹 빌드의 안정성이나 접근성을 해치지 않는가?
- 사용한 에셋과 기술을 합법적으로 공개·배포할 수 있는가?
- 제한된 기간 안에 Codex와 함께 구현하고 테스트할 수 있는가?
- 3분 이내 시연에서 가치가 드러나는가?

## 제출 전 완료 조건

- 현장에서 심사위원이 직접 플레이 가능한 상태 확인
- 심사 기간 전체의 URL 가용 계획 확인
- 로그인이 필요하면 작동 확인된 심사용 테스트 계정과 사용 방법 제공

- 공개 URL에서 브라우저 웹 빌드 실행
- 별도 승인 없이 접근 및 플레이 가능
- 핵심 플레이 루프 완주 가능
- 첫 화면에서 조작법과 목표 확인 가능
- 치명적 오류 없이 반복 플레이 가능
- 외부 에셋 출처와 라이선스 목록 작성
- Codex 활용 기록 및 사람의 결정 사항 정리

- 3분 이내 발표와 시연 동선 준비

## 권리 관련 주의

- 제출작의 저작권과 지식재산권은 원칙적으로 참가자에게 귀속된다.
- 행사 운영·심사·홍보·아카이브 목적의 제출 자료 이용이 허용될 수 있다.
- 수상 시 공모전 종료 후 4개월 동안 사업화·투자·퍼블리싱·공동개발에 관한 주최·주관사의 우선 협상 기회가 적용된다.
- 정확한 법적 조건은 제출 시점의 공식 참가 약관을 다시 확인한다.
