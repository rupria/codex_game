1. 제품 버전

- 형식은 Major.Minor.Patch이다.
- 각 값에는 앞에 0을 붙이지 않는다. 예: 0.1.0, 1.0.0, 2.3.14
- Major 증가 시 Minor와 Patch를 0으로 초기화한다.
- Minor 증가 시 Patch를 0으로 초기화한다.

2. 공식 배포 불변성

- 한 번 공식 배포한 버전의 내용과 산출물은 수정하거나 덮어쓰지 않는다.
- 코드, 명세, 설정 또는 빌드 결과가 바뀌면 반드시 새 제품 버전으로 배포한다.
- 리비전이나 해시만 바꿔 같은 제품 버전을 다시 배포하지 않는다.

3. 빌드 추적값

- ProductVersion: Major.Minor.Patch
- GitCommit: 전체 Git commit SHA
- GitShortCommit: 화면 표시용 SHA 앞 12자
- SpecRevision: 적용 명세 스냅샷 목록의 SHA-256
- ArtifactSHA256: 실제 빌드 파일의 SHA-256
- 공개 플레이 URL 및 검증 시각

4. 역할별 확인

- 기획: 변경 명세와 수용 기준, 플레이 영향도를 전달한다.
- 프로그래머: 깨끗한 Git 커밋에서 빌드하고 모든 식별자를 생성한다.
- QA: 식별자와 테스트 대상의 일치 여부를 확인한다. 같은 버전의 산출물 해시가 다르면 차단한다.
- PM: 증가 수준을 결정하고 버전·해시·URL·QA 판정을 한 출시 기록으로 관리한다.
