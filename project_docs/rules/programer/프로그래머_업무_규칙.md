# 프로그래머 업무 규칙

> **역할:** 합의된 기획을 안정적인 웹 게임으로 구현하고 코드·테스트·Git 이력을 안전하게 관리한다.

## 작업 위치

- 기술 검토와 작업 메모: `G:\내 드라이브\codex_game\obsidian\core\programer`
- 실제 Git 저장소: `C:\sk-encoa\codex_game`
- 게임 코드와 코드 산출물: `C:\sk-encoa\codex_game\programer`

## 작업 시작 전

- 대상 파일과 관련 규칙을 다시 읽는다.
- 실제 Git 저장소에서 `git status --short --branch`를 확인한다.
- 미추적 파일, 다른 작업자의 변경과 동시 작업 여부를 확인한다.
- 기술 스택 확정 전 특정 프레임워크 구조를 만들지 않는다.

## 구현 제한사항

- 요청에 필요한 최소 파일과 최소 범위만 수정한다.
- 게임 로직과 플랫폼 종속 기능을 가능한 한 분리한다.
- 코어 플레이를 로그인·결제·외부 API·비밀 키에 의존시키지 않는다.
- 비밀번호, API 키, 인증 토큰과 개인정보를 저장하지 않는다.
- 출처와 라이선스를 확인하지 않은 코드·에셋을 포함하지 않는다.
- 검증 기준을 낮추거나 테스트를 비활성화해 오류를 숨기지 않는다.
- 관련 없는 파일을 정리하거나 다른 작업자의 변경을 수정하지 않는다.

## 제출 형식 관련 필수 구현사항

- 별도 설치 없이 브라우저에서 바로 실행되는 웹 빌드를 만든다.
- 심사 기간 동안 유지 가능한 공개 HTTPS 플레이 URL을 제공한다.
- 초대와 개별 승인 없이 링크만으로 게임에 접근할 수 있게 한다.
- 로그인은 가능한 한 제거하고, 불가피하면 심사용 테스트 계정 흐름을 지원한다.
- 첫 화면 또는 즉시 확인 가능한 위치에 조작법과 실행 방법을 표시한다.
- 외부 API, 비밀 키, 비용 한도와 인증 장애가 기본 플레이를 막지 않게 한다.
- pub 통합 시 배포 산출물과 플레이 URL을 재현할 수 있는 빌드 절차를 제공한다.

## Git 제한사항

- 한 커밋에는 하나의 명확한 목적만 포함한다.
- 커밋 전 변경 파일과 diff를 확인한다.
- 다른 작업자의 변경을 확인 없이 함께 커밋하지 않는다.
- 강제 푸시, 강제 초기화와 이력 재작성은 합의 없이 하지 않는다.
- 푸시와 PR 전에 저장소, 브랜치와 변경 범위를 확인한다.
- GitHub 인증이 확인되지 않으면 권한이 있다고 가정하지 않는다.

## 빌드 버전 책임

- 승인된 `Major.Minor.Patch`와 깨끗한 Git 커밋에서 공식 빌드를 만든다.
- 전체 Git SHA, SpecRevision과 ArtifactSHA256을 생성해 QA에 공개 URL과 함께 전달한다.
- 기존 공식 버전은 수정·덮어쓰기하지 않으며 변경분은 새 버전으로 만든다.
- 상세 기준: [[../버전관리/BUILD_VERSION_POLICY|빌드 버전 관리 정책]]

## 완료 조건

- 구현 목적과 수용 기준을 충족한다.
- 실행·빌드·테스트 결과와 미검증 범위를 기록한다.
- QA에 변경 범위, 테스트 방법, 알려진 제한과 빌드를 전달한다.
- QA와 PM에 공개 플레이 URL, 지원 환경, 배포 시각과 알려진 접근 제한을 전달한다.
- Codex 작업은 `문제 → Codex 활용 → 사람이 결정한 내용 → 결과`로 기록한다.
