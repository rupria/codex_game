## 승인 원칙

- 검증하지 않은 항목은 `PASS`로 처리하지 않는다.
- 공개 링크 접속, 플레이 시작 또는 핵심 루프 진행이 막히면 `P0`다.
- 로컬 빌드 검증과 공개 URL 검증을 구분한다.
- 같은 ProductVersion의 ArtifactSHA256이 기존 기록과 다르면 배포를 차단한다.

## 판정

- `PASS`: 필수 조건 충족, 제출 차단 결함 없음
- `CONDITIONAL`: 플레이 가능하나 알려진 제한과 승인된 위험이 있음
- `FAIL`: 필수 조건 미충족 또는 플레이 진행 차단
- `NOT TESTED`: 검증하지 않음

## 기능·재미 검증

- [ ] 처음 보는 플레이어가 30초 안에 목표와 기본 조작을 이해한다.
- [ ] 3분 안에 카드 펼치기·벨 경쟁·카드 선택·승패 예측을 경험한다.
- [ ] `게임진행플로우_0.03`의 구현 수용 기준을 충족한다.
- [ ] 시작·진행·성공·실패·전투 종료·재시작 흐름을 완료한다.
- [ ] 플레이어 입력과 AI 반응에 즉각적인 시각·음향 피드백이 있다.
- [ ] 반복 플레이에서 진행 차단과 저장 상태 오염이 없다.

## 공개 링크 필수 검증

- [ ] 새 브라우저 또는 시크릿 창에서 링크 하나만으로 접속된다.
- [ ] 설치·초대·개별 승인·유료 결제 없이 실행된다.
- [ ] 로그인 없이 플레이된다. 불가피한 경우 제출용 계정이 실제 작동한다.
- [ ] 첫 화면 또는 즉시 확인 가능한 위치에서 목표·조작법·실행 방법을 찾을 수 있다.
- [ ] 지원 브라우저·화면 크기·입력 방식에서 핵심 루프를 완료한다.
- [ ] 성공·실패 후 다시 플레이할 수 있다.
- [ ] 마지막 정상 접속 시각과 심사 기간 가용 계획이 기록돼 있다.

## 제출 자료 검증

- [ ] 제출 폼의 URL과 검증 URL이 같다.
- [ ] 게임 화면 안내와 제출 설명의 조작법이 같다.
- [ ] 로그인 필요 시 테스트 계정과 사용 안내가 포함돼 있다.
- [ ] 외부 코드·에셋·폰트·음원의 출처와 라이선스가 확인됐다.
- [ ] 공개 링크 소유자·갱신 담당자·장애 대응 담당자가 기록돼 있다.

## 회귀 검증 조건

다음 중 하나가 바뀌면 새 ProductVersion 또는 새 후보 빌드 식별자를 받아 관련 범위를 다시 검증한다.

- 코드·빌드 설정·배포 환경
- 게임 규칙·수용 기준·명세 스냅샷
- 에셋·데이터·외부 의존성
- 공개 URL·로그인·접근 권한
