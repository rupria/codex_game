# 제출 링크 및 pub 운영

- 담당 역할: PM
- 기준일: 2026-08-05
- 관련 프로젝트: <https://github.com/users/rupria/projects/2>
- 관련 PM 이슈: <https://github.com/rupria/codex_game/issues/4>

## 브랜치 운영 결정

- 일반 기획 연계, 개발, 문서화와 QA는 `dev`를 우선 기준으로 진행한다.
- `pub`은 통합된 빌드에서 실행 파일 또는 공개 웹 빌드를 산출하는 브랜치다.
- PM이 `pub`의 웹 빌드와 제출 링크 운영을 관리한다.
- 사용자의 별도 요청이 있을 때만 `pub` 반영과 웹 빌드 작업을 시작한다.
- 이번 문서 최신화에서는 `pub`에 커밋, 푸시 또는 병합하지 않는다.
- `dev` QA 통과는 `pub` 제출 후보의 자동 승인을 의미하지 않는다.

## pub 작업 시작 조건

- [ ] 사용자의 명시적 `pub` 작업 요청
- [ ] 통합할 `dev` 커밋 SHA 확정
- [ ] 필수 기능 범위와 알려진 제한 기록
- [ ] 빌드·배포 재현 절차 확인
- [ ] 공개 HTTPS URL 소유자와 갱신 담당자 지정
- [ ] 장애 복구 담당자와 연락 방법 지정
- [ ] QA 회귀 범위와 제출 차단 기준 확인

## 일정 게이트

- `D-5`: 공개 HTTPS URL에서 플레이 가능한 후보 빌드 확보 및 신규 기능 동결
- `D-4`: 시크릿 창·무승인 접근, 현장 입력 환경, 테스트 계정과 조작 안내 검증
- `D-3`: 최종 URL 동결, 담당자·복구 절차 확정, 실제 제출 및 접수 확인
- `D-2 ~ D-1`: 링크·플레이·제출을 막는 P0 장애만 대응

## 제출 후보 승인 조건

- 공개 HTTPS URL이 실제로 존재한다.
- QA가 시크릿 창에서 링크 하나로 핵심 플레이를 완료한다.
- 설치, 초대, 개별 승인, 지역 제한과 유료 결제가 없다.
- 로그인 필요 시 작동 확인된 테스트 계정과 사용 안내가 준비된다.
- 조작법과 실행 방법이 게임 화면과 제출 설명에서 확인된다.
- 심사 기간 가용성, 갱신 담당자와 장애 복구 담당자가 기록된다.
- 하나라도 충족하지 못하면 제출 준비를 `Done`으로 처리하지 않는다.
