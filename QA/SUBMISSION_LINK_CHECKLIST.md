## 접근 검증

- [ ] 새 브라우저 또는 시크릿 창에서 공개 링크 하나로 접속된다.
- [ ] 별도 설치 없이 브라우저에서 실행된다.
- [ ] 초대, 개별 승인, 지역 제한과 유료 결제가 없다.
- [ ] 로그인 없이 플레이할 수 있다.
- [ ] 로그인이 불가피하면 제출용 테스트 계정으로 실제 로그인된다.
- [ ] 테스트 계정 사용 방법과 전달 방식이 확인된다.
- [ ] 첫 화면 또는 즉시 확인 가능한 위치에서 조작법과 실행 방법을 찾을 수 있다.

## 플레이 검증

- [ ] 지원 브라우저와 예상 현장 입력 환경에서 조작할 수 있다.
- [ ] 핵심 플레이 루프를 처음부터 끝까지 완료할 수 있다.
- [ ] 성공·실패 후 재시작할 수 있다.
- [ ] 새로고침 후 다시 플레이할 수 있다.
- [ ] 외부 API 장애 또는 비용 한도가 기본 플레이를 막지 않는다.
- [ ] 치명적 콘솔 오류, 무한 로딩 또는 진행 차단이 없다.

## 제출 자료 일치 검증

- [ ] 제출 폼 URL과 검증한 URL이 일치한다.
- [ ] 게임 화면의 조작 안내와 제출 설명이 일치한다.
- [ ] 로그인 필요 시 테스트 계정과 사용 안내가 제출 자료에 포함된다.
- [ ] URL 소유자와 장애 복구 담당자가 기록돼 있다.
- [ ] 마지막 정상 접속 확인 시각이 기록돼 있다.

## 역할 및 브랜치 제한

- QA는 기획, 코드, 빌드 설정과 배포 설정을 직접 변경하지 않는다.
- 실패 항목은 GitHub 결함 Issue 또는 명확한 수정 요청으로 담당자에게 전달한다.
- `dev` 검증과 `pub` 통합 빌드 검증을 구분해 기록한다.
- 사용자의 별도 요청이 없으면 `pub`에 커밋, 푸시 또는 병합하지 않는다.
